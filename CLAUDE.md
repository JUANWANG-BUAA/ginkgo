## What this is

Ginkgo (BUAA Assistant) is a native Swift/SwiftUI client for BUAA campus services (CAS login, schedule, grades, library seats, classroom availability, check-in, homework, graduate academic, tasks). **The current and only development target is Android with Flutter + Rust (`flutter/`, `rust/`).** The native macOS/iOS apps (`BUAA-Assistant/`, `BUAA-Assistant-iOS/`) are **frozen**: no feature work, no cross-platform parity work, no Apple-only scheduling — fix them only reactively when they break the Android build, a shared fixture, or a security issue. Windows shares the same Flutter project: no feature work, but shared changes must keep it compiling. Start current work with `docs/ANDROID-DEVELOPMENT.md`, `docs/MIRROR-IMPLEMENTATION.md` and the sole unfinished list `docs/MIRROR-TODO.md`; the Swift architecture and Xcode commands below apply to Apple work only, not the default mainline. The 2026-10-24 engineering / design / UI review, rescoped to Android-only, is at `docs/_audit/2026-10-24-comprehensive-review.md` and its P0/P1 ordering drives the current backlog. Current tree `e149f90` removed homework-to-personal-task creation UI; preserve old local records, do not restore that entry based on the historical first-iteration plan. All traffic goes directly to upstream BUAA systems (or through the school's official WebVPN gateway `d.buaa.edu.cn`) — there is no self-hosted relay server. Docs, UI strings, and commit messages are Chinese; keep that convention.

Android / shared Rust + Flutter (from repository root):

```sh

cd flutter && flutter build apk --debug --target-platform android-arm64 --target lib/main.dart
```

See `flutter/README.md` for tools and normal/demo entry points; do not use an integration-test APK as the normal app. Only regenerate FRB bindings when its API changes. The following commands are for the independent Apple targets.

The optional live-account test reads `GINKGO_LIVE_USERNAME` / `GINKGO_LIVE_PASSWORD` from the process environment only — never commit credentials.

## Architecture

### Two shells, one shared source tree

`BUAA-Assistant/` is shared Swift source compiled into **both** apps. The macOS Xcode project is filesystem-synchronized (new `.swift` files are picked up automatically); the iOS project includes `../BUAA-Assistant` and excludes macOS-only files via the `excludes:` list in `BUAA-Assistant-iOS/project.yml` (app entry, `RootView`, `MainView`, every macOS feature page, `Core/Keyboard`, `Core/LaunchAtLogin`, `Core/Notification`, `PageComponents`, `MacViewModifiers`, Assets). Consequences:

- Cross-platform code: add the file, no macOS project edit; run `xcodegen generate` for iOS.
- macOS-only shared file: also add it to the `excludes:` list in `project.yml`.
- Entry points: macOS `BUAAAssistantApp.swift` → `RootView` → `WorkspaceHost` → `MainView`; iOS `GinkgoiOSApp.swift` → `IOSRootView` → `WorkspaceHost` → `IOSMainView` (per-page UI in `Sources/Native/IOS*View.swift`). `WorkspaceHost` creates the shared `WorkspaceCoordinator`, which owns every feature ViewModel; `WorkspaceLifecycleModifier` holds the cross-platform orchestration (check-in polling, reminders, WebVPN state, foreground/network refresh).

### Global state and session lifecycle

`AppState` (`@MainActor`, injected as `@EnvironmentObject`) owns login state: `restoreSession()` validates the existing cookie via `uc/api/uc/status` first, and only if confirmed invalid silently re-logs in from the Keychain credential (captcha blocks silent login). `WorkspaceHost` (`.id(account)`) owns the `WorkspaceCoordinator`, which holds every feature ViewModel so switching pages preserves state and account switches release the whole workspace. Business-system auth failures must be re-confirmed through UC (`confirmSessionAfterAuthFailure`) before clearing the local session — upstream 5xx jitter must not kill the login state.

### Networking and route abstraction (read before touching any client)

- `APIClient.shared` provides four URLSessions: `session` (business requests, follows redirects), `noRedirectSession` (CAS auth chain, manual hop-by-hop redirect handling), plus `webVPNSession` / `webVPNNoRedirectSession` backed by an **in-memory-only** cookie store. Direct and WebVPN cookies must never mix.
- `UpstreamRoutePreference` (`automatic` / `direct` / `webVPN`, UserDefaults) is the user-facing route. In automatic mode, an upstream access-policy denial switches the preference to WebVPN and retries once; route changes clear cookies and force re-login (`applyUpstreamRouteChange`).
- All upstream requests go through `URLSession.routedData(for:noRedirect:)` (`Core/Network/UpstreamRoute.swift`). In WebVPN mode it rewrites BUAA URLs to the gateway, strips direct `Cookie` headers, and normalizes responses/redirects back to the original URLs. **Never hand-roll a URLSession call in a feature client, never re-serialize `httpBody`, and never hand-set gateway cookies** — the graduate schedule and SPOC role endpoints return empty data if you do (ARCHITECTURE.md §9.1.3).
- Feature clients are `actor`s that take a session and build requests against upstream bases, with parsing isolated in a separate parser type (e.g. `ScheduleClient` + `ScheduleParser`). Tests must exercise the route abstractions — do not hardcode `d.buaa.edu.cn` in feature clients.

### Auth (CAS)

`CasClient` implements the flow: `fetchLoginPage()` (parse `execution`, captcha, hidden fields — replay all hidden fields, never hardcode the field list) → `login()` with manual redirect-chain walking and error detection → `validateSession()` via `uc/api/uc/status` (`code == 0` + non-empty `data`). TGT/ST tickets are managed entirely by cookies (`HTTPCookieStorage`; CASTGC is HttpOnly — never hand-build Cookie headers). Passwords only in Keychain (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`).

### Storage

- Credentials: Keychain (`Core/Storage/KeychainManager.swift`), one device-only record.
- Query snapshots: Codable JSON files under Application Support; filenames are isolated per account via SHA-256 digest of the account (digest ≠ encryption). Caches are versioned envelopes; a failed refresh keeps the previous cache. Per-module retention limits are documented in ARCHITECTURE.md's "当前实现说明" section.
- Preferences: UserDefaults. Logging: `AppLog` (OSLog) — every `catch` should leave at least one log line before deciding to swallow or throw.
- Shared helpers (reuse instead of re-implementing): `LocalStore` / `SnapshotCache` (per-account JSON files), `SchoolTime` (Asia/Shanghai calendar, fixed-format dates, clock parsing), `JSONValue` (lenient field coercion), `HTMLText` (entity decoding / plain text), `FormURLEncoding`, `AESCipher`, `AutoRefreshGate` (auto-refresh cooldown), `CasPageParser.isLoginRedirect`, `StatusPresentation` (status titles/symbols/tints), `GraduateCredit`, `WorkspaceCoordinator` / `WorkspaceHost`.

### Feature module layout

`Features/<Name>/` groups Client (actor, network), Models/Parser, ViewModel (`@MainActor` `ObservableObject`), and View. `Core/` holds Network, Storage, Logging, UI (`CrossPlatformSupport.swift` for cross-platform colors/images, `PageComponents.swift` for shared states), Update, and the macOS-only Keyboard / LaunchAtLogin / Notification subsystems.

### Tests

`BUAA-AssistantTests/` is shared by the macOS target and the iOS `GinkgoiOSTests` target (`project.yml` references `../BUAA-AssistantTests`); `@testable import BUAA_Assistant`. Use XCTest with synthetic data (`sy2501001`, `李文`) and mocked responses; cover parser edge cases, session failures, and changed business rules; add regression tests for fixes. iOS UI smoke tests live in `BUAA-Assistant-iOS/UITests/`.

## Project-specific rules (from docs/COLLABORATION.md — violating these gets a change rejected)

1. **Evidence for upstream assertions.** Any claim about an upstream URL, parameter, field, success code, or auth format must cite `docs/API.md`'s verified (✅) sections or source evidence. No citation → mark it `⚠️ 待验证`, never state it as fact. Never invent endpoints.
2. **Never "unify" upstream success codes.** Systems differ (`"0"`, `"1"`, Int 0, `code ∈ {0,1}`) — this is upstream reality, not a code smell.
3. **Privacy.** Real student IDs, names, cookies, tickets, or HAR files must never appear in code, tests, docs, snapshots, or fixtures. Logs redact with `privacy: .private`.
4. **Write operations never auto-retry.** Booking/check-in/reservation POSTs are user-triggered only; on unknown outcome, stop and ask the user to verify rather than resending (retries can invert upstream state). Generic retry logic must not apply to writes.
5. **Security-sensitive diffs need human review**: Keychain access, TLS trust, logging output, entitlements/network permissions. Consult `docs/COLLABORATION.md` before changing auth, TLS, entitlements, or upstream writes.
6. **Never hand-edit `.xcodeproj` files.** iOS: edit `BUAA-Assistant-iOS/project.yml` and regenerate with XcodeGen. macOS: describe the required target/config change for the maintainer to apply in Xcode.
7. **Distinguish expected failures from defects** in UI copy (e.g. "not logged in" vs a bug), and give actionable guidance for the former.
8. **Commits**: concise Chinese with a topic prefix (e.g. `修复：…`); branch as `feat/<module>` or `fix/<issue>`; keep `main` usable. Protocol corrections require updating `docs/API.md`'s revision table.

Code style: two-space indentation, `UpperCamelCase` types, `lowerCamelCase` members, files named after their primary type (`ScheduleViewModel.swift`), `@MainActor` on UI state, parsing isolated from networking.

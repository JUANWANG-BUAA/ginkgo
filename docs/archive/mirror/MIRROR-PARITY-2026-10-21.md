## 实现与交互

- Rust 为已选记录与统计分别增加领域投影、独立缓存和读取用例。列表保留选课记录 ID、嵌套课程、选课时间、考勤、通过状态和成绩；统计保留有效课程数和分类的应完成/已完成数量。未知值保留为未知；结构漂移/重复记录拒绝，避免部分数据覆盖完整快照。
- `CourseDetails` 的配置仍只导出存在性；真实姓名、作业正文、原始签到配置不进入桥接。退出和清缓存同时清除两类快照。
- BYKC 远程读取按模块顺序激活认证；已有新鲜快照读取不等待远程锁。目录加载不依赖已选或统计，首次进入对应分段才请求。加载、错误、重试和旧内容分别保存，用户仍可切换分段。
- 前端课程与已选记录使用懒构建列表；目录保留搜索/类别。已选记录可进入详情查看选课时间、成绩及考勤，详情打开不发新请求。大字号用选择器替代挤压的分段控件。
- 完成统计以明确文字、计数、进度条表达；超额保留真实计数但进度条最多填满，0/0 显示“本项暂无要求”，不显示仍需完成。没有有效学期范围时，已选页说明无法查询，不宣称零条记录。

## SPOC 正文缺失调查与类型漂移修复

主代理真实读取列表后，第一条详情 `failure == null`、`content == null`。逐层核对：Flutter/Rust 服务会剥除一次 `spoc:` 命名空间；HTTP 只用一次 `form_urlencoded` 生成 `id`/`kczyid`；端点、键名与 Swift `SpocHomeworkClient.loadDetailOnce`、UBAA `LocalSpocApi.LocalSpocClient.getAssignmentDetail/getSubmission` 一致。合成带 `+ / %` 的 ID 回归确认编码后解码等于原值，无重复编码。

`zynr` 在 Swift 与 UBAA 中均为可空字符串。缺失/null/空白/纯标签会得到无正文，但不必然代表详情请求失败；`docs/API.md` §7.1 已有原生端 2026-10-16 某条正文未返回、其他详情字段可用的记录。本轮完整真实验收确认首条详情发布时间、截止时间和分值存在，正文与提交时间为空；仅记录字段存在性，不保存原始个人数据。没有把接口成功推定为正文可用，也没有强加上游未验证的 id/title 必填条件。

调查发现确定性解析缺陷：原 `optional_string` 把对象/数组形式的 `zynr` 静默变成 `None`，并会用“成功空正文”覆盖旧完整缓存。修复为严格可空字符串，结构漂移返回 `ChangedResponse`，旧详情快照保留。新增对象/数组 2 份合成 fixture 与应用缓存回归；在旧实现上二者明确失败，恢复修复后通过。另新增 adapter 回归证明可空正文与可用元信息/提交状态共存，带保留字符 ID 只编码一次。未执行额外真实登录/设备操作；此结构修复不被宣称为当前真实空正文的根因。

## 首次签到与执行报告延迟审查

针对主代理实测首次签到 9863ms、执行报告 10226ms，检查 `checkin_service` / `checkin_http`、`graduate_service` / `graduate_http`、共享 `auth::session`、`reqwest_transport`，并对照 Swift `CheckInClient.currentSession` 与 `GraduateAcademicClient.activate/loadPlanExecution`。未新增实网请求、设备操作或阶段性能日志，未改协议、TLS、路由回退或上游写入行为。

发现并修复两个可合成复现的签到重复工作路径：

- Rust 原先等课程读取成功后才保留已成功登录的 iclass session；Swift 在 app login 成功后即保留。现提前缓存成功会话，课程 HTTP 503 / 结构漂移不再导致下次重跑 SSO 与 app login；业务拒绝、认证失效仍清除相应会话。合成链路中失败后重试总计 9 次 HTTP 调用（含初始学校登录 5 次），第二次只读取课程；没有隐式重试失败的课程请求。
- 并发普通读取同一冷缓存日期原先可能各自认证、查询。现用签到模块异步 gate 串行网络链，取得 gate 后复查日期快照；同日并发只用一个 entry + app login + course query，初始学校登录合计 8 次 HTTP 调用。新鲜日期快照在 gate 前直接返回，不等另一日期的慢请求；显式 force refresh 仍分别访问上游。不同未缓存日期的网络读取会按序执行，避免争用共享 iclass 会话。

新增 4 项确定性应用回归覆盖上述两类情况、force refresh 保留与新鲜快照不等待；已有签到失效恢复、WebVPN 回退、历史日期隔离及一次提交回归继续通过。研究生既有 fresh cache 快路径与 gate 后复查无需再改；加强成功报告回归，明确学籍不加载报告、报告仅激活对应 app 后调用执行报告端点，不走培养方案回退或重复学校登录。

首次无缓存签到仍需走 SSO entry 重定向、app login、课程查询；成功执行报告仍需 app 激活（可含重定向）再查询。共享标准 Mutex 均在网络 await 前释放；Graduate 的异步 gate 有意串行共享 GSMIS 网络链，未发现这次顺序验收发生排队的证据。连接超时仍是 6 秒、单请求总超时 30 秒；仅凭 9.9 / 10.2 秒总耗时无法区分 DNS/TCP/TLS、重定向、WebVPN 或上游处理，更不能据此修改超时或省略服务激活。本次减少重复工作，不宣称这两个首次成功样本已缩短，也不推断 P95。

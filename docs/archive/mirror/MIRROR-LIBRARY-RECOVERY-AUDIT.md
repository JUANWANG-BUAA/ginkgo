# 图书馆迟到失效响应复核（2026-10-21）

> **历史归档（2026-10-21 收敛）**：本文保留当时的实现、计划或验收证据，文内“当前”与计数仅适用于原记录。最新状态见 [实施现状](../../MIRROR-IMPLEMENTATION.md)、[待办](../../MIRROR-TODO.md)、[功能对照](../../MIRROR-PARITY.md)。普通文字中的源码路径仍以仓库根目录为基准。

场馆和当前预约现可并行读取。二者使用旧token时，先返回的失效响应触发认证换得新token；另一个旧请求随后返回失效，原 `reset_library_token` 会无条件清除新token，导致额外CAS交换与等待。

本次使用响应所属请求的token做条件失效：仅当内存token仍等于该请求被拒绝的token时才清除。另一个读取已成功恢复时复用新token。每条只读路径仍至多重建一次，写路径不添加认证重发。此修复作用于历史、场馆、分区、时段、座位与当前预约的已有只读恢复分支，不改变HTTP协议。

源码参照：UBAA `LocalLibBookApi.kt:268–326` 的requestJson/ensureLogin区分读取与认证锁；Ginkgo镜像现有library_token锁内复查保护首次登录。此次修复针对迟到失败与新token的竞争，不宣称UBAA原实现已规避该竞争。

确定性回归先模拟“新token已恢复，旧请求迟到失效”的状态，在原实现失败；修复后新token保持、认证HTTP请求数为0。另验证当前token匹配时确实清除。相关library过滤测试24项通过，含单次失效恢复、并发首次登录、缓存失败保留及写操作不重放。真实账号延迟仍需当前网络验收，不由此推定所有卡顿已消失。

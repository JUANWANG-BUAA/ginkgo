# Android 下一次发布的强制验收契约

生效：2026-11-02。用户明确反馈：本日修复前的 Beta 在实际使用中不可用。此前“本地门禁通过”“已做视觉验收”不能作为当前可发布证明。**Beta.7 与 Beta.8 分别于 2026-11-03 按用户直接指令在 readiness 仍为 `blocked` 时公开；两次均属发布门禁例外，不代表契约验收通过。** 历史发布记录保留其当时证据，不追改为当前已通过。

## 1. 可发布的含义

“接近 100% 流畅、功能完整”落实为：当前公开承诺及可达入口的主流程、详情和操作闭环全部验收；P0（登录/核心功能不可用、账号/数据/写入安全）和 P1（主要流程失败、卡死、无法恢复、明显操作障碍）均为零。不能用增加测试数量、隐藏既有功能、放宽成功判断或修改测试预期换取通过。尚未支持的路线/资格/功能必须在入口前准确说明，不冒充成功、空数据或已完成。

外部学校服务可能临时不可用，不能承诺永不故障；客户端必须保留错误含义、已有成功数据及时间，给出有界等待、取消/返回与恢复入口。学校故障不伪造登录成功，不循环重试密码，不重复写入。

流畅性在物理 Android 的 profile/Release 包测量：本地点击反馈目标 100ms 内、已有页面切换目标 300ms 内、连续滚动掉帧目标低于 1%；记录设备、刷新率、采样方法和 p95/掉帧。网络耗时单列，不能混同本机卡顿或用平均值掩盖长尾。未达到目标的主要操作作为 P1 处理，不能只写“感觉流畅”。初次启动、前后台、键盘、返回、旋转、大字号、深浅色、TalkBack 与重复点击都必须有操作记录；静态截图不足以证明。

## 2. 必须覆盖的链路

- 登录：正确/错误密码、首次验证码、答错后的新 execution、刷新、过期、图片失败、网络失败、UC 目录失败、身份不符；失败原因可辨、旧答案失效、单次提交和未知结果不重发。
- 路线：登录前选择自动/直连/WebVPN；校内、校外和本次“校园网加宿主隧道”的环境分别记录，不能由 Mac 可达推断 Android 可达。明确模式不擅自改变，匿名公开读取隔离。
- 会话：保存/不保存密码，冷启动/强停/前后台、Cookie 轮换、退出、账号切换、旧响应、24 小时边界；Android Keystore/JNI 实际往返。密码保存和 Cookie 恢复分别验收。
- 全功能：`workspace_catalog.dart` 每个目的地及其详情、筛选、分页、刷新、失败恢复；本科/研究生及权限差异用对应合资格账号验证。不仅首页能打开，课表、作业/学习、成绩/教务、图书馆、签到等必须能实际完成承诺任务。
- 学校写操作：已开放的图书馆、签到、CGYY、个人文件作业由本人选择真实业务、确认单次提交并回查；结果不明只回查。代理不自动提交；合成写测试不代替此项，缺证据保持阻断。
- 本机操作：设置逐项修改并重启核对；覆盖保存失败后的显式重试、连续保存的最终值、读取失败停止自动恢复，以及重读后保留主动退出选择；待办/课程范围/快捷入口/提醒独立保存；权限/通知类别/重启/账号隔离；查询缓存清理不得删除个人记录或待核实保护。
- 安装升级：正常入口签名候选覆盖旧版，保留本机数据、发现更新、下载校验/中断恢复与系统安装；Windows 共享改动必须有远端 Windows 构建与测试证据。认证、保险库、TLS 改动须维护者安全审查。

## 3. 机器门禁与证据绑定

[协议锁](protocol-contracts.json) 记录三组协议/客户端契约的源码与文档摘要、不可违反的规则和回归出处。`check-contracts.py` 检查输入覆盖、引用和摘要；修改源码/协议文档而未同步审查会失败。它能发现漂移，**不能证明协议事实正确或人工报告真实**。

```sh
python3 scripts/check-contracts.py
python3 scripts/check-contracts-test.py
python3 scripts/check-contracts.py --show-required
python3 scripts/check-contracts.py --candidate
python3 scripts/check-contracts.py --release
```

前两项进入完整门禁和 mirror CI；Android tag workflow 在准备签名之前执行 `--release`。发布记录 [android-release-readiness.json](android-release-readiness.json) 仍为 `blocked`。缺失、待验、失败、错误证据层级、P0/P1 未归零、候选摘要或版本不符均会使自动发包拒绝继续；不提供跳过参数。机器必验项由脚本固定规则和功能登记表共同计算，不能从 JSON 删掉失败项使其通过。Beta.7 与 Beta.8 的公开资产均按用户明确要求在该门禁被阻断后手动上传；详见当日审计。

每个验收项填入 `cases`：`status: passed`、要求的 `level`、仓库内脱敏 `report` 路径、报告内唯一 `section` 标识、ISO `date`、`environment`、具体 `result`。报告必须含当前候选源码完整摘要，明确构建/设备/网络/步骤/预期与实际结果，不能搬用旧报告。真实读、本人写、模拟器、物理设备、人审、Windows CI 分层记录。候选摘要包括未提交实现文件、脚本、workflow、锁文件与 fixture，不包含验收记录本身；加入证据不会导致摘要自引用。版本号来自 pubspec，不能作为发布证明。

协议/实现变更先改 API 对应章节和修订记录、本地契约和回归，再执行 `python3 scripts/check-contracts.py --refresh-lock`。刷新仅确认这次审查的文件摘要，**绝不把发布状态改为通过**。候选源码变化或协议锁变化后，旧发布验收自动失配；维护者完成针对该候选的复核后才能记录新摘要和 `ready`。既有 APK 签名/ABI/正常入口/公开下载校验仍要执行，本文不替代产物检查。

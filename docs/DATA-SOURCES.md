## 3. 余额查询专项（本次维护者决策）

### 3.1 允许范围

- **校园卡余额**、**网费余额**：只读、单次、用户主动触发。
- 展示：金额默认遮挡（如 “¥ ••••”），点击/长按后显示；不显示卡号、姓名、宿舍等附加信息。
- 缓存：进程内存 5 分钟；退出页面/登出/账号切换即清空；不写入查询快照、不写日志、不写 UserDefaults。

### 3.2 禁止范围

- 缴费、充值、挂失、转账、修改支付密码、绑定/解绑银行卡。
- 消费明细默认不展示；如后续要做，需单独评审并默认关闭。
- 不得使用余额接口做轮询或批量查询。

### 3.3 取证前提（当前 ⚠️）

1. 维护者本人登录后，按 COLLABORATION §2.2 导出**脱敏 HAR**，确认：
   - 余额接口的 host、方法（只读 GET 优先）、参数、成功码；
   - 是否依赖 CAS 会话、WebVPN、企业微信 OAuth；
   - 失败/未登录的返回形态（401/302/业务码）。
2. 在 `API.md` 新增 ⚠️ 章节并登记修订表；真实只读验证通过后才改 ✅。
3. 写操作（缴费）**不进入**本项目的接口清单。

### 3.4 验收

- 余额与学校官方页面一致；断网/失败保留上次值并提示“可能过期”；
- 页面不出现任何缴费/充值按钮；
- 日志无金额、卡号、Cookie。

## 4. 明确不做

| 项 | 原因 |
|---|---|
| 缴费/充值/挂失/转账 | 资金写操作，安全红线 |
| 续借提交、预约/取消、签到、评教提交、请假/审批提交 | 写操作，改变上游状态，需人工确认且不自动重试 |
| 推免/评优/拟推荐/获奖名单正文 | 含他人姓名/学号，隐私红线 |
| 通讯录、他人课表/成绩 | 他人个人信息 |
| 成绩单/在读证明下载 | 含完整个人信息，且涉及打印/收费流程 |
| 校历 OCR、校园地图 POI | 仅图片，无结构化数据，成本收益不成立 |
| 就业岗位列表/详情 | 仅 POST + token，公开只读不可得 |
| 验证码绕过、后台批量抓取 | 违反项目红线与上游规则 |

## 5. 取证与落地流程

1. 公开源：先补 `API.md` ⚠️ 章节（来源、字段、频率、失败形态），实现只读 Service/Parser/ViewModel/View，合成 fixture 测试。
2. 登录源：维护者本人浏览器操作 → 脱敏 HAR → AI 归纳端点/字段 → 维护者抽查关键断言 → `API.md` ⚠️→✅。
3. 余额：按 §3.3；只读验证通过后再实现，且默认遮挡、内存缓存、无日志。
4. 写操作：一律不进自动重试；提交前二次确认、提交后回查、结果不明不重发（COLLABORATION §3.5）。
5. 验收：每项在 `ACCEPTANCE.md` 记录日期、账号类型、脱敏结果；写操作单独列“未验收”。

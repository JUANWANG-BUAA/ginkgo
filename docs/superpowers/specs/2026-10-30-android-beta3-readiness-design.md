# Android Beta.3 候选准备设计

## 目标与范围

把当前工作树收敛为可验收的 Android Beta.3 候选：先修复设备/真实账号验收管线的依赖注入，再修复独立能力替换时的旧状态与迟到响应，最后执行完整门禁、正常入口构建、真实账号只读验收和签名候选产物检查。本批不增加学校功能，不自动执行学校写操作，不把模拟器或合成测试写成真实业务验收。

## 方案

采用小步原地修复，而非重构验收框架或推迟到发布后：

1. 研讨室、研究生学分地图和真实验收页面显式注入与工作区相同的读写端口；演示测试只使用 `DemoMirrorService`，真实验收只使用 `NativeMirrorService`。
2. 将 `bookingGateway`、`creditMapGateway`、`academicService` 纳入各自页面的身份代次。能力变化时清除该能力的状态、取消旧结果落地并重新读取；不改变本地待办存储身份，也不触发任何写命令。
3. 用可控 `Completer` 回归证明旧能力响应不会出现在新能力页面，再跑分层测试和 `bash scripts/check-mirror.sh`。
4. 版本冻结后构建正常 `main` ARM64 包。真实账号验收仅做只读页面与登录链路；学校写操作仍由本人逐次指定并确认。签名、覆盖升级、公开下载与 GitHub 发布分别记录，未执行项明确保留。

备选方案是只修测试注入、不动页面状态，改动更小但会留下同类账号/服务替换风险；或一次性统一所有页面控制器，长期收益较高但会扩大候选版回归面。选择上述局部方案。

## 验证与交付边界

- 每个状态修复先新增能复现旧响应落地的失败测试，再实现并转绿。
- 设备演示测试必须实际进入目标页面并断言关键内容，不能只验证 pump 无异常。
- 完整门禁和正常入口构建是候选必要条件；真实账号、物理设备、Release 覆盖升级与签名结果独立记录。
- 未经用户后续明确授权，不推送 tag、不公开 GitHub Release，不执行真实预约、取消、签到或作业提交。

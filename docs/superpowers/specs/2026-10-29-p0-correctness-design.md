# 第一批 P0 正确性优化设计

日期：2026-10-29

## 目标与范围

在不改变学校协议、不增加功能、不做无关 UI 重构的前提下，修复三个已定位的正确性问题：退出登录超时后的假成功、新增网络错误码导致的恢复型快照失效，以及提醒超时恢复后的旧响应覆盖。每个问题先用现有测试框架复现，再做最小实现修改。

本批不处理缓存票据容量、运行时初始化恢复、Dart 契约循环、写命令类型和设备验收；它们进入后续独立批次，避免扩大审查面。

## 1. 退出登录必须真实吊销

当前 bridge 在全局会话写锁超时后直接返回 `SignedOut`，但负责清理身份和 Cookie 的闭包可能尚未执行。

设计原则：本地吊销是安全动作，不能因排队或超时而被跳过，也不能向 Flutter 伪造完成状态。实现应尽量复用现有 `SchoolClient.sign_out()` 的身份代次、Cookie 清理和快照失效逻辑，不新增第二套退出状态机，也不改变写操作在途时的账号隔离规则。

回归场景：先建立已认证状态并占住会话读锁，使退出无法及时取得写锁；推进到闸门超时后，断言返回前本地身份已被吊销，而不是只检查 DTO 的 `SignedOut`。同时保留现有“退出等待在途读”和正常退出清理测试。

## 2. 暂时性网络失败统一允许恢复快照

`NetworkUnreachable` 与 `ServiceUnavailable` 都表示可尝试使用有效旧快照的暂时性失败；认证、权限、协议变化和非法请求仍不得借旧数据伪装成功。

在共享错误语义层提供统一分类，替代 `SnapshotCache` 与 `SnapshotBook` 中对单个错误码的重复比较。恢复型条目仍必须满足原有 TTL、账号、代次和路由约束；本修改不延长成功时间，也不让过期快照重新生效。

回归场景：准备仍在 TTL 内的 restored 条目，分别以 `NetworkUnreachable` 和 `ServiceUnavailable` 完成失败读取，二者都返回旧值和原失败；以 `SessionExpired` 读取则继续拒绝回退。通用缓存与 domain 快照信封都要覆盖新错误码。

## 3. 提醒刷新统一丢弃旧代次

`BusyGate` 超时只重新开闸，不取消旧工作。课程和待办已有规划 ticket，签到与作业缺少同等保护。

为提醒刷新增加统一的轮次标识：每次实际开始 refresh 时取得单调递增的轮次，签到和作业在网络 await 后仅当轮次仍是最新且控制器未销毁时才更新。课程和待办保留现有 ticket，不用重复改写其规划逻辑。`reconcile()` 只消费最终接受的计划，不改变通知平台串行替换规则。

回归场景：第一轮签到和作业读取挂起，使 BusyGate 到期；第二轮读取先返回新数据并落地，再释放第一轮旧数据。断言旧数据不能覆盖第二轮计划，也不能触发以旧数据为准的新排程。

## 验证与交付边界

1. 新增测试在未改实现时分别失败，修改后通过。
2. 运行相关 Rust、Flutter 专项测试，再运行 Rust workspace 测试、严格 Clippy、Flutter analyze 和 Flutter 全量测试。
3. 最终运行 `bash scripts/check-mirror.sh` 和 `git diff --check`；若接口索引仍因本批之外的改动过期，单独记录，不能宣称完整门禁通过。
4. 不使用真实凭据，不执行学校写操作，不把合成测试写成真实业务验收。
5. 保留用户现有未提交改动，不做提交、重置或清理式 git 操作。

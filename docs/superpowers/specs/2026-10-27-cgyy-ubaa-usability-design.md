# CGYY 研讨室 UBAA 对照可用性修复设计

日期：2026-10-27  
状态：已获用户确认，进入第一批实施  
范围：Android（Flutter + Rust）；Windows 仅保持共享代码可编译  
参考：UBAA `LocalCgyyApi.kt`、`CgyyApi.kt`、`CgyyLockCodeScreen.kt` 与 `docs/features/cgyy.md`

## 1. 目标

修复当前研讨室“入口存在但核心流程不可用”的产品缺口：

1. 学校用途读取失败或返回空列表时，不再让整个预约表单失效。
2. 预约记录支持查看单条订单详情。
3. 接入门锁密码查询，展示密码、有效期和对应预约信息。
4. 首页提供清晰的“预约研讨室 / 我的预约 / 门锁密码”入口。

本批不重做课表、研究生教务或 SPOC 页面；这些沿用已确认的后续批次。

## 2. UBAA 对照结论与安全边界

采用：

- `/api/codes` 失败或无有效用途时的内置用途降级思想。
- `GET /api/orders/{orderId}` 订单详情。
- `GET /api/orders/lock/code` 门锁码及 `orderView` 预约摘要。
- 门锁页区分密码可用、未到开门时段、当前无可用预约。

不采用：

- UBAA 验证码失败后最多三次的提交循环。
- 登录恢复后不加区分地重放 POST。
- 门锁页每 30 秒自动轮询。
- 为对齐 UBAA 而删除 Android 已有的空档复核、单次提交、账号代次或待核实保护。

UBAA 与当前 Rust 的验证码主结构均为 `code=200 → data → success/repData`，此前官方前端静态 `repCode` 差异不能直接作为本次故障根因。本批不修改验证码成功码，除非新的失败 fixture 证明需要变更。

## 3. 分层设计

### 3.1 Domain

- `BookingOptions` 增加 `uses_fallback_purposes: bool`，让页面知道用途来自内置降级而非本次学校读取。
- 复用现有 `CgyySource::load_cgyy`，为 `CgyyQuery` 增加 `Order { order_id }` 与 `LockCode`，为 `CgyyData` 增加对应的 `Order` / `LockCode` 投影，不另建平行读取服务。
- 新增 `CgyyLockCode` 值类型，只包含 UBAA 已使用的字段：`qrCode`、`dueDate`，以及 `orderView` 中的 `tradeNo`、场地、空间、预约人、日期、时段和开始/结束时间。未知字段忽略，不把原始 JSON 跨层传递。

### 3.2 Upstream

- 保留现有固定直连、签名、token 和账号代次规则。
- 用途解析先尝试学校结果；空结果或允许降级的读取失败使用 UBAA 的 10 项内置用途。
- `session_expired`、验证码、凭据错误不得被用途降级掩盖。
- 降级只发生在 `booking_options`，不修改通用 CGYY envelope，不把其他模块的结构漂移当成成功。
- 订单详情与门锁码作为独立 GET 接入；允许现有“token 过期后最多恢复一次”的只读规则，仍执行 await 后账号复检。
- 门锁码不写入快照、待办、诊断或普通偏好，不使用后台轮询。

### 3.3 Core / bridge / Dart gateway

- core 继续转发同一个 `load_cgyy` 端口，不加入学校字段或协议判断。
- bridge 在现有 `load_cgyy` 中识别 `order` 与 `lockCode` 两种 kind，使用 45 秒 `bounded_read`，返回 Rust 净化后的领域投影；函数签名不变，无需重新生成 FRB。
- `CampusGateway.cgyy` 签名不变；`cgyy_gateway.dart` 增加订单详情和门锁码的领域辅助函数，demo 通过现有 `load_demo_cgyy(kind)` 提供合成数据。
- 现有页面模型只解码净化后的领域 JSON，不手改任何 FRB 生成文件。

### 3.4 Flutter

- 首页：
  - “预约研讨室”进入场馆选择；
  - “我的预约”进入订单列表；
  - “门锁密码”进入独立页面。
- 预约表单：使用内置用途时显示非阻塞说明“学校用途暂未取得，已使用内置用途列表”。
- 订单列表：每条有效订单可打开详情；详情失败可重试，不用空订单替代失败。
- 门锁页：
  - 有非空且非 `"null"` 的 `qrCode`：大字显示密码与有效期；
  - 无密码但有预约摘要：显示“未到开门时段”；
  - 无密码且无预约摘要：显示“当前无可用预约”；
  - 读取失败：显示错误与重试，不显示成无预约；
  - 仅手动刷新，离开页面即丢弃显示状态。

## 4. 错误与隐私

- 门锁密码、预约人、手机号、学校 token、Cookie、验证码和原始响应不得进入日志。
- 门锁密码只读失败与“确认无密码”分开；空响应不推断学校没有预约。
- 订单详情和门锁码采用账号隔离；飞行中切换账号时旧结果不得写入新页面。
- 本批不新增学校写操作，不自动执行预约、取消或验证码提交。

## 5. 测试设计

先写失败回归，再实现：

1. 用途：学校正常列表、空列表、允许降级失败、认证失败不降级、内置列表完整且稳定。
2. 订单详情：UBAA 形态字段映射、HTTP/业务错误、token 恢复一次、账号切换拒绝迟到结果。
3. 门锁码：有效密码、`qrCode="null"`、有预约但无密码、完全空数据、结构漂移、敏感值不进诊断。
4. 页面：三个首页入口、fallback 提示、订单详情导航、门锁三态、错误重试、手动刷新、大字号完整密码。
5. 既有安全：全部 CGYY 既有测试保持通过，写命令次数与待核实状态不变。

完成后运行 `bash scripts/check-mirror.sh`、`git diff --check`，构建正常 `lib/main.dart` Android ARM64 包，并用合成数据检查三个入口和门锁页截图。

## 6. 验收边界

- 合成测试和 Android 截图只证明客户端流程，不证明当前学校账号可预约或可开门。
- 真实预约、取消仍须用户逐次确认并回查，代理不执行。
- 门锁密码需在用户授权下做一次真实只读核对；未核对前不得宣称真实开门能力已验收。

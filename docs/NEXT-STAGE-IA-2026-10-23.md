## 1. 设计结论

1. 信息增加必须先分清“下一步事项”和“服务入口”，不能把 i 北航入口逐项堆到 Today 尾部。
2. 过渡期保留现有五个底栏；提供清楚的“全部服务／搜索服务”入口，打开独立目录页。
3. 推荐目标为“工作台｜签到｜课表｜作业｜服务”，仅将第五栏预约迁入服务目录；**须先评审确认，不默认实施**。
4. 领域 hub 组织低频功能；同一服务的多处入口指向同一稳定目的地，不复制页面、状态或学校会话。
5. Today 保留一个课程主焦点、少量近期事项和用户置顶服务；个人资料与消息不各占一个新底栏。
6. 一般扩展先做已取证、低风险的只读闭环；用户明确要求的阳光打卡列为 P1 手动写入闭环，须通过专项写门禁。入口观察、成功空样本、静态源码线索均不升级为完整协议或业务验收。
7. 保持银杏主题、现有分组和语义色；扩大信息结构，不重写设计系统、不强制全量 Material 化。

## 3. 本轮新增观察如何影响设计

以下是父代理本轮转交的观察摘要；方法、字段、样本边界以协议研究记录为准。

| 证据范围 | 已观察 | 仍未证明 | 设计影响 |
| --- | --- | --- | --- |
| 匿名公开图书目录 | `search`、`hot1`、`new/books`、`holdings` 返回 `code 0` | 完整分页、全部状态和榜单指标语义 | 可提高公开查书闭环的取证优先级，不宣布全部接入 |
| 馆藏返回形态 | `holdings` 内容是 JSON 字符串，而非已结构化数组 | 所有分支都采用同一编码形态 | 解析与异常态需专项样例，不让页面直接解析学校响应 |
| 本人借阅 | `loans` 返回 `code 0` 且为空 | 非空记录字段、应还日期、续借条件 | 可记录成功空态；不能据此冻结非空模型或承诺借阅摘要 |
| 校车本人查询 | 列表显示 12 班且余票有差异 | 匿名可见性、身份资格、所有余票类别与购买权限 | 可继续只读建模；展示按身份和查询时刻限定，不跨账号复用 |
| CGYY 官方静态线索 | `page 0`、`weekStartDate` 取响应首项、验证码尺寸 330→310 | 最终写入、取消、审批及其业务成功 | 作为协议修订线索；本轮未执行写，不作为预约验收 |
| 更多 i 北航服务 | 工作台上观察到若干教学、图书、生活、健康、网络、办事、就业入口 | 对应数据协议、权限和写入流程 | 只作为功能候选，不承诺原生实现 |

`code 0` 仅说明该次观察的返回；不能推导统一成功码，更不能证明所有账号和时间均可用。
`hot1` 的存在不自动证明“全校借阅热门榜”；榜名、统计周期、校区和排序口径须另核实。
校车列表中的余票不等于本人必然可订；12 班是该次查询结果，不固化为每天班次数量。
本轮观察与旧方案的“当时未登录／未获得成功样本”按日期并列保留，不改写历史事实。

## 4. 导航过渡与推荐迁移

### 4.1 过渡方案：保持原五栏

- 底栏仍为“工作台｜签到｜课表｜作业｜预约”，不增加第六栏。
- 工作台在标题区下方提供轻量“搜索服务／全部服务”入口；目录是独立二级页面。
- Today 原底部手写目录在未来评审中迁出；过渡时可保留“全部服务”单行，不复制整份目录。
- 目录新增服务以领域分组承载；用户无需先滚过课程、作业和任务才能寻找低频功能。
- 现有预约入口和操作方式不因新候选出现而改变，不把文档阶段视为迁移授权。

### 4.2 推荐目标：第五栏预约改为服务

- 目标五栏为“工作台｜签到｜课表｜作业｜服务”，保留高频学业栏的顺序和短名称。
- “空间资源”成为服务页显著 hub；原预约聚合页可继续作为其目的地。
- 原 `reservations` 稳定 ID 和用户已保存快捷项保留；新增 `services` ID，不把旧 ID 偷换语义。
- 用户已选“空间预约”仍直接到原空间 hub，不先绕一次全部服务目录。
- 不因迁移清空置顶顺序、重设默认项或丢失原查询筛选；升级迁移须有合成回归。
- 首次迁移只需一次可关闭说明：“预约仍在服务中的空间资源，也可固定到工作台”。
- 不把“消息”“资料卡”“校园卡”各自升为底栏，避免导航随服务数量增长。
- 迁移是否执行须看手机样板、主要任务可达性、返回路径和大字体验，不能只按功能数量决定。

## 5. 手机目标布局与文本线框

### 5.1 工作台：回答下一步做什么

```text
工作台                         设置   刷新
搜索服务／全部服务                         ›
日期 · 今日课程
┌ 下一节／正在进行 ──────────────────────┐
│ 课程标题（允许换行）                    │
│ 时间 · 地点 · 来源／上次同步           ›│
└───────────────────────────────────────┘
学校作业                  查看全部 ›
  最多三项可行动作业；未知截止单独说明
个人待办                  查看全部 ›
  一个优先事项＋少量次要事项／无截止入口
常用服务                         编辑
  用户明确选择的 0–4 个入口
工作台    签到    课表    作业    预约
```

- 课程为唯一主焦点；其余分区以标题、数量、动作行建立层级，不做多块等权彩色广告牌。
- 新的临近借阅／预约摘要只有在可复用已知状态、用户开启且不阻塞首屏时评审接入。
- 不在 Today 默认放余额、借阅、余票、医疗、成绩多张个人数据卡；不能借摘要要求预拉全部系统。
- 学校作业与本机任务仍独立；截止分类采用专项统一规则，不随首页布局顺带删除逾期个人任务。

### 5.2 服务目录：回答去哪找

```text
服务                               搜索
[ 搜索服务名称／别名                    ]
常用服务                         编辑 ›
学业             图书与借阅
空间资源         校园生活
校园资讯与就业   健康／网络／办事
────────────────────────────────────────
图书与借阅                            ›
  查书、馆藏、本人借阅（能力按证据开放）
空间资源                              ›
  图书馆座位、教学楼研讨室、空教室
────────────────────────────────────────
官网入口带“前往官网 ↗”，不伪装应用内功能
```

领域可用简短入口行或自适应两列；窄屏／大字退单列，不依赖横向滑动标签才能发现服务。
未取证的候选留在研究文档，不在正式目录铺大量灰色“即将上线”；没有可用目标不展示假按钮。

### 5.3 领域 hub：统一模板而非统一业务

```text
‹ 服务       图书与借阅
查书／书目检索                           ›
新书／官方推荐                          ›
我的在借                   主动查询      ›
官方读者服务                  官网 ↗    ›
来源与更新说明；局部失败只影响本项
```

hub 使用标题、简短说明和少量动作行；不要求先登录全部子系统，也不把多个系统合并成同一会话。

## 6. 领域归属与候选分级

| 领域 | 优先候选（默认只读，阳光打卡例外） | 目前只留官网或继续取证 |
| --- | --- | --- |
| 学业 | 既有课表、作业、成绩体验；本人考试安排、全校课表须新证据 | 注册、请假、自助打印、证明、第二课堂申报 |
| 图书与借阅 | 公开查书／书目／馆藏；本人在借先补非空样本 | 书架、预约／委托、借阅违章处理、续借写入 |
| 空间资源 | 既有空教室、座位和教学楼研讨室查询 | 新观察的图书馆研讨间／柜流程，不混为 CGYY |
| 校园生活 | 可溯源校车计划时刻；有资格边界的余票只读继续取证 | 校园卡充值支付、报修提交、校车购退票 |
| 校园资讯与就业 | 现新闻网通知；公开指南、招聘与宣讲信息先审来源 | 就业报名、材料递交、办事申请与审批 |
| 健康／网络／办事 | 阳光打卡 P1：手动填写、确认提交、记录回查（写门禁）；低敏感公开说明 | 挂号、公费医疗、心理、网络开通缴费等原生办理 |

- 公开查书是 P1 候选；热门展示需先解释统计口径，无此证据则叫新书／推荐或不展示。
- 本人借阅是条件式 P1：成功空态可确认，非空详情和提醒仍待验证；默认不持久化、不自动轮询。
- 校车动态余票是条件式候选，不因本次成功列表就默认新增购票按钮或后台刷新。
- 医疗心理、阅读历史和消费信息不因“只读”而变成低风险；不默认聚合或跨域索引。
- 本阶段排除自动签到、抢票、自动占座、自动续借、代理支付、代办提交、他人数据读取和未授权画像。
- 官网入口也须验证目标与跳转边界；不携带凭据，不承诺免登录，不把打开入口等同授权办理。

### 6.1 阳光打卡：明确需求的 P1 手动写入闭环

用户已明确要求“阳光打卡需要写操作提交的功能”，不能将需求降为 P2 只读记录或永久官网入口；**本轮仍只设计，不实现、不真实提交**。
阳光打卡与现有 iClass 课程签到是不同业务；保留现有签到 tab 的课程语义，阳光打卡进入健康领域 hub，不增加底栏、不合并提交状态与角标。

1. 进入服务目录“阳光打卡”→读取官方适用条件／当前可填内容→用户手动填写与选择材料→本地校验→确认页→用户明确点击提交一次→记录列表／详情回查。
2. 官方体育／艺术静态已读链中，地点为手填 `place` 与 `place_type`，未见定位字段／SDK；**首期不申请定位权限**，仅后续学校确有要求时另行取证与评审。表单其余字段和资格按实际条件开放，不假造地理校验。
3. 官方静态默认 `isopen=1` 会公开到广场；客户端可提议新草稿向学校请求 `isopen=0`，但关闭值的真实契约必须先验证，不能宣称已改变官方默认。确认页显著展示本次公开范围；证据不足时应写“请求不公开，学校是否接受待确认”，不得标成“已私密／不会公开”，无法验证则阻断真实提交。确认页同时展示填写内容、照片预览、适用活动与提交后果；返回修改不提交，提交中禁连点，切账号清除旧草稿与回调。
4. 成功受理与最终记录／审核状态区分；以可验证记录标识和回查结果定位本次提交。超时、断连、解析失败或回查未匹配显示“结果待核实”，禁止自动重试、恢复登录后重放或把未匹配当失败重新提交。
5. 写门禁为：官方流程和字段／媒体上传语义、身份与活动资格、成功／失败／待核实判定、记录匹配与跨重启防重复策略均有证据，并经人工安全评审；真实写验收仍须用户逐次授权。
6. 已读官方静态要求至少 1 张、最多 3 张本人照片，每张不超过 5MiB；相机／相册按实际支持和用户动作使用最小权限，拒绝、无设备、读取失败均给操作说明。当前不申请定位；官方若限定照片来源，不能擅自替换。多图先上传（也是写）再 `clockin`；上传结果未知不得自动重传，最终提交结果未知亦不得重发。
7. 不自动打卡、补卡、批量提交，不伪造坐标、照片、活动时间或运动记录，不用旧材料静默替换本次材料；不得绕过官方限制凑出“可提交”。
8. 工作台只提供用户置顶入口或用户主动开启的本机提醒；提醒不自动提交、不承诺官方资格，不默认展示活动照片、地点或填报内容。详情及材料不进入全局服务搜索与最近使用画像。
9. Windows 先评估照片获取与上传能力，当前不以定位作为前提；缺少官方所需能力或官方不支持该环境时，明确说明并回退已验证官网，不用模拟材料冒充能力，也不宣称跨端完整可用。
10. 周／月超额与非周期提示在已读链中来自提交后响应；不得据此假装已有提交前资格校验并本地拒绝。只按已验证条件做前置校验，提交后按真实响应解释、回查，不能借提示自动改类重投。

验收覆盖手动填写→修改→确认→照片上传→单次提交→记录回查，另含公开范围默认请求关闭且文案不误导、1–3 张／5MiB 边界、取消、权限拒绝、上传未知、重复点击、提交后条件提示、重启恢复、会话过期与账号切换；合成流程测试不代替真实学校写入验收。

## 7. 跨域服务搜索

1. 第一阶段仅搜索本地目录元数据：名称、别名、领域和说明；明确提示“搜索服务，不检索个人记录”。
2. 支持“查书／图书检索”“课程表／课表”等有限可审查别名，不自动猜测不存在的服务端能力。
3. 结果按应用内服务／官网入口区分；显示领域与简短说明，避免多个“预约”“研讨室”无法辨认。
4. 搜索本身不触发所有系统登录和请求；点击某结果后才按该服务权限与加载规则打开。
5. 第二阶段可评审书目、公开通知等已验证域的内容搜索，用户须明确选择范围。
6. 默认不搜索成绩、借阅、医疗、个人消息，也不扫描账户缓存建立隐形全局索引。
7. 服务搜索与书目检索分别命名；无结果、尚未接入、网络失败、身份不可用分别呈现。
8. 返回保留搜索词、选定领域与滚动位置；清空搜索不清除学校数据或个人待办。
9. 搜索历史先仅当前会话保存，不写诊断日志；持久化、推荐与统计须另行评审。
10. 可设计 `ServiceDescriptor` 的 ID、名称、别名、领域、目的地、能力类别和敏感级别；这些是客户端提议，不是学校字段。

## 8. 资料卡、消息与常用服务

### 8.1 资料卡

- 资料卡是“本人主动查询后的已知状态”，不是默认收集个人档案的“我的”首页。
- 可从头像／设置附近进入独立页面；设置保留偏好、账号与诊断职责，不混成学校个人信息汇总。
- 借阅、校园卡等按系统独立卡，标来源、覆盖范围与最近成功读取；敏感值默认隐藏，用户分别开启。
- 原则上点击卡才读取；离页、登出、切账号清理敏感临时状态，迟到响应不得入新账号界面。
- 个人借阅持久化、到期通知、后台截图遮罩等都须另评审，不能写成当前已有能力。

### 8.2 消息

- 暂保留“校园通知”和“本机提醒”的不同来源；个人学校消息待协议取证后才讨论统一入口。
- 消息已读、提醒已读、本机任务完成、学校作业提交是四种状态，不互相代替。
- 学校返回的数量与本机计划数量不直接相加成“统一未读”；官网查看也不自动宣称学校已读。
- 消息中心不抢占新底栏；有可靠内容和未读语义后，再评审工作台标题区低权重入口。

### 8.3 常用服务与隐私

- 沿用显式置顶 0–4 项、保存／取消与账号级顺序；不默认根据点击次数自动重排。
- 当前空选择与默认选择有区别，未知 ID 仍保留；见 `workspace_shortcut_preferences.dart:9–21,62`。
- 读取偏好失败不先闪默认项；切账号销毁编辑草稿；见 `workspace_shortcuts.dart:74–82,167–214`。
- 官网项显示 ↗；固定入口不代表允许预拉该服务。若以后做最近使用，须可关闭、可清除，敏感服务默认不记。

## 9. 一致状态、Windows 与验收

### 9.1 数据和动作一致性

- 每域区分未请求、初次加载、确认空、成功、旧值更新中、旧值失败、登录待确认与权限不符。
- 未知余额／余票／数量显示“未查询／待确认”，不显示 0、售罄或没有记录。
- 每来源独立显示最后成功时间和覆盖日期；整页刷新成功不代表所有卡都已同步。
- 复用 `RefreshSection` 的单飞、保旧值和销毁后拒绝迟到结果（`application/refresh_section.dart:11–47`）。
- 摘要与详情使用相同来源与投影规则；写结果未知必须提示回查，不提供自动重发或假成功。

### 9.2 Windows 与自适应

- 沿用 760dp 桌面断点、248dp 侧栏及 Today 820dp／普通内容 900dp 上限，见 `design/tokens/layout.dart:8–19`。
- 桌面侧栏先工作台与常用，再领域组／hub；不能每新增功能就增加永久顶层行。
- 同目录、同稳定 ID；手机底栏与桌面侧栏只是不同承载，不各建一套服务业务定义。
- 现桌面 `reservations` 被映射到 `library`（`workspace_shell.dart:351–352`），未来空间 hub 不能照搬该降级语义。
- 保留首次访问才建页、独立栈、隐藏页不抢焦点和停止 ticker；不因双栏一次初始化所有子服务。
- 支持键盘 Tab、Enter、Escape、焦点返回来源；窗口变窄和跨断点切换应保留当前任务与筛选。

### 9.3 设计验收规格

- 手机 320dp、常规宽度、系统大字 2.0、深浅色与七主题均检查；48dp 触控起步，文字换行而非缩字号。
- TalkBack 可读标题、来源、时间、状态与动作；错误和选中态不能只靠颜色，减少动态立即到终态。
- 路径覆盖：工作台→搜索→服务→详情→返回；旧空间快捷项→空间 hub；各 tab 保栈与 Android 返回不退出错页。
- 状态覆盖：首次空、首次失败、旧值失败、局部成功、会话过期、资格不符、A→B→A 与迟到结果。
- 搜索覆盖：别名、同名预约、无结果、官网标记、返回恢复，以及搜索不触发学校全模块请求。
- 迁移覆盖：0 项置顶、未知 ID、旧 `reservations` 偏好、保存失败、升级不覆盖用户顺序。
- 图书覆盖：馆藏 JSON 字符串解析失败、空借阅与未查询有别；未测非空字段不得造假样本冒充观察。
- 校车覆盖：来源日期、查询身份范围、未知余票、旧结果失败；不以静态人数推算余票。
- 本轮只交付设计文档，不以文档完成声称导航、接口、Android 真机、Windows 构建或学校写入已验收。

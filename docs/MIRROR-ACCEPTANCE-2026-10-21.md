## 验收边界

- 自动化单元 / 契约 / widget 使用合成数据。Android 合成 FFI smoke、真实账号只读、公开网站请求和人工视觉分别记录，不互相替代。

- 签到与图书馆写路径此前已有确认、单次提交、回查与未知结果处理；实现及合成测试不能表述为本轮真实写入通过。BYKC / CGYY 写入、作业作答 / 提交 / 附件下载尚未迁移。
- 研究生账号不能证明本科教务通过；空成绩不能证明非空成绩与 GPA 正确；Windows CI 文件存在不能证明 Windows 主机已通过。完整学分地图、提醒、全量读屏仍有差距。
- 旧文档中的测试总数与真实记录仅对各次日期有效。本轮最终总数以同一工作树的收口运行结果为准，不累加重复测试。

## Windows 主机结果

**尚无结果。** 独立入口为 `flutter test integration_test/windows_test.dart -d windows`，CI 先执行 Windows debug 构建和 Flutter tests；主机真实执行后再填写构建、Credential Manager 合成往返、侧栏 / 详情导航与窗口交互结果。当前没有公开 Windows 安装包。

本机静态与合成构建审查修复了三处阻断：Rust manifest 从真实 Cargokit 根定位，避免依赖 Flutter 符号链接父级数量；冷构建先创建 DLL 输出目录；集成测试后恢复 `lib/main.dart`，避免上传测试入口。Windows批处理增加首次 `.dart_tool` 目录及失败码传播，CI 校验 exe / Rust DLL / Flutter DLL / ICU / assets。新增 `python3 scripts/check-mirror-windows-cmake.py`，直接与符号链接路径各 Debug / Release 共四配置通过；同一脚本内的隔离 stand-in 在两种配置下实际执行 CMake 构建和 DLL 复制，通过冷输出目录验证。这些均不等于 Windows 主机编译或批处理执行通过。

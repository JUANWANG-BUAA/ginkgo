# Ginkgo 学生核心任务与信息交互设计

日期：2026-10-31。版本：1.0。基线：`efdad39`（工作树提交，不代表公开发布）。

本文整合同学对改版前的反馈、改版后代码及模拟器画面复核、产品取舍和实现验收要求，供维护者与 coding harness 执行。**本文定义 A–E 学生核心 UX 设计；其实现、测试和设备证据见 [逐页视觉审计](_audit/2026-10-31-ui-ios-language-restore.md)，工作树改动不代表已发布。** 未完成事项及实施状态唯一登记在 [MIRROR-TODO.md](MIRROR-TODO.md) 的持续 UI Goal；本文中的需求编号用于引用，不另维护任务完成勾选。

## 1. 产品定位与成功标准

Ginkgo 面向北航学生，优先解决学习与校园日常中的高频任务：查看安排、处理作业、查看并手动完成签到、寻找图书馆资源。产品投入优先保证这些任务可靠、易找、易懂，扩展能力按人群需求和维护成本决定。

“满足 90% 需求”来自同学的经验判断，当前没有使用数据支持，不能当作统计结论，也不能据此直接删除模块。交互流畅是本次同学反馈中的正面评价，应保留现有导航反馈与异步体验；减少内容时不能引入整页阻塞和反复加载。

| 投入层级 | 范围 | 产品约束 |
| --- | --- | --- |
| 核心任务 | 课表、作业、签到、图书馆 | 优先修复可靠性；高频路径短；默认首页展示相关事项 |
| 人群任务 | 博雅、研究生教务、就业活动等 | 保持可发现；允许常用入口；不默认占据首页 |
| 辅助服务 | 其他查询、公开资讯与官网入口 | 集中目录；明确原生能力与官网跳转；不为填满首页增加读取 |

隐藏入口不减少协议和维护负担。功能退出支持必须另有依赖、使用需求、替代路径、用户数据保留与迁移评估；本文不批准删除功能、修改学校协议或扩大学校写能力。

设计成功通过具体任务验证：用户能判断现在有什么要处理、找到目标功能、理解数据是否可信，并完成或安全退出操作。测试通过、截图数量、token 使用比例只作为证据，不替代上述判断。

## 3. 适用范围、依据与冲突处理

实现范围为 Android 的 Flutter UI；Windows 共享代码保持可编译。iOS 标准用于导航与控件语义参考，冻结的 SwiftUI 应用保持冻结。Android 系统返回、键盘、安全区、至少 48dp 触控目标和 TalkBack 继续适用。

事实依据：

- [逐页视觉审计](_audit/2026-10-31-ui-ios-language-restore.md)：记录当前修正与模拟器证据。
- [UI-DESIGN.md](UI-DESIGN.md)：当前共享组件、视觉 token 和历史设计约束。
- [学生工作台设计](STUDENT-WORKBENCH-DESIGN-2026-10-28.md)：历史产品背景；当前结构以源码及本设计的明确差异为准。
- [API.md](API.md)、[INTERFACE-INDEX.md](INTERFACE-INDEX.md)：协议与契约事实。两个课表来源的覆盖及签到映射未经核对不得作假设。
- [Apple Action sheets](https://developer.apple.com/design/human-interface-guidelines/action-sheets/)：操作表用于用户发起操作后的相关选择，并应谨慎使用。下文尺寸、首屏预算和投入分级为项目设计决定，不冒充 Apple 官方阈值。

本文明确修订的目标规则如下；其他既有约束继续有效。实施以 Android / Flutter 为主，并符合 iOS 的导航与控件语义，同时遵循 Android 的返回、安全区、键盘、48dp 最小触控与 TalkBack 约束。未来实现必须同步对应准则、静态门禁与有意义的行为回归，不能直接移除检查或提高预算来掩盖冲突。

| 当前规则 | 本设计目标 | 实施约束 |
| --- | --- | --- |
| 卡片内不出现读取、查询等主动作 | 首次读取空态和局部失败允许就地按钮；全页刷新仍在工具栏/下拉 | 对首次、刷新、重试分别建模；不得把所有按钮移入卡片 |
| 其余功能只在更多出现一次 | 目录内去重；业务域内允许语义明确的上下文入口，如图书馆内借阅 | 复用同一目的地及状态，不复制功能页或创建两套业务实现 |
| 每页必须额外有汇总 | 在有判断价值时汇总；筛选、状态行或列表可承担同一职责 | 不为了门禁制造摘要卡；未加载不造计数 |
| 来源与时间只能一行 | 常规字号尽量紧凑；大字号和异常状态允许换行 | 原成功时间、过期及异常不能因省略而不可理解 |
| 8 项以内操作表，更多用滚轮 | 按任务语义选择 | 控件数量只影响布局，不决定控件类别 |
| 冻结 Apple 页面语义逐项对应 | 保留系统交互语法，允许本设计列明的产品优化 | Apple 源码为实现参考，不能覆盖 Android 平台约束与新决策 |
| 首页不设置聚合时间线 | 保留 | 优化现有分区、课程焦点和状态，不重复聚合相同事项 |
| 服务搜索使用二级页面 | 目标为更多页直接可输入搜索 | 复用已有本地检索与结果呈现，不增远端搜索、不复制索引 |

## 4. 信息架构与导航契约

移动一级标签保留：**今天 / 课表 / 作业 / 图书馆 / 更多**。现有数据不足以证明这组标签对所有学生最优，本轮不再次调整标签。

```text
今天：当日安排与需要处理的已有事项 → 对应业务详情
课表：周/日安排 → 课程详情 → 对应签到详情/确认
作业：状态筛选与作业列表 → 作业详情
图书馆：当前有效预约 + 找座位 / 找书 / 本人借阅
更多：常用服务 + 本地搜索 + 分组目录 + 账号与设置
```

NAV-01：上下文跳转复用 `workspace_catalog.dart` 的稳定目的地及已有导航能力；同一功能可从不同任务进入，但不得产生重复读取职责或不同版本的页面。

NAV-02：跨一级目的地使用现有 shell 切换语义；领域详情使用现有路由栈。返回回到来源、保留合理滚动/筛选；取消未提交操作不提交学校请求。深层页面不得出现重复返回控件。

NAV-03：目录置顶只改变目录排序，原分组不重复列出；搜索可以命中置顶项。业务上下文入口不受目录去重限制。

NAV-04：业务页工具区只放本页常用操作；有数据可刷新，无读取能力不显示伪按钮。账号与设置放在更多的明确固定入口，目录搜索也应可找到；不要求新增第六个标签。

## 5. 页面设计规格

### 5.1 今天：回答“今天有什么、现在需要处理什么”

TOD-01：保留已有课程、考试、签到、作业、本机待办及通知分区，不新增横跨来源的时间线。默认展开课程焦点和确有待处理内容的分区；已完成记录折叠，资讯放在日常任务之后。

TOD-02：课程焦点展示课程名、可靠的起止时间、地点、可确认的签到提示。正在进行的可行动事项在所属分区内置前。不能仅凭“未签到”推断签到窗口正在开放，不能凭系统日期把旧课表当今天。

TOD-03：普通分区默认最多展示 3 条，超出提供“查看全部”；这是项目起始预算。当前可行动的异常和待核实操作不受该数量静默隐藏，必须有可见提示及进入路径。稳定顺序优先，不在用户点击时突然重排分区。

TOD-04：成功且确认无内容的常规分区隐藏或收成一句摘要。失败、部分成功、旧数据保留相邻提示。考试成功且确认无有效记录时隐藏，不新增空占位；首次读取失败必须可见并可重试，有旧数据时保留记录并显示失败与原成功时间。任何失败都不能被呈现为“今天没有考试”。

TOD-05：默认不展示全部服务目录，不新增余额、新闻或低频办事卡片。自定义首页属于后续受控扩展，入口可跳过；原有“常用服务”偏好不能直接冒充“首页内容”偏好。

### 5.2 课表与签到：整合课程场景

SCH-01：周次、回本周、日期与课程为主体。课程卡片优先名称、时间、地点；教师和来源放详情。重叠课程仍可发现，不为整齐省略其中一门。

SCH-02：课程详情在可靠关联时展示签到状态及入口。没有可靠关联时说明“尚未关联签到记录”，提供独立签到列表，不显示“不需要签到”。

SCH-03：关联依赖已有稳定标识、课程场次及时间语义；不以相似课程名合并。关联规则不足时先核实 domain / upstream 契约，不在 Dart 猜测两个学校来源等价。

SCH-04：签到入口先进入详情或确认，逐目标提交一次并回查。显示课程不触发签到；时间线、通知或卡片点击不能自动提交。独立签到页继续承载历史、异常及无法关联的记录。

### 5.3 作业：先找到要处理的作业

HW-01：课程范围改为紧凑入口；优先顺序为当前范围提示、主状态筛选、搜索、必要附加筛选、作业列表。管理课程角色不再占据独立大卡片。

HW-02：主筛选为全部 / 待完成 / 已提交；“待确认”通过明确筛选发现。截止为独立维度：未截止 / 已截止 / 时间未确认。与主筛选同时使用时显示当前条件和“清除筛选”，不能让用户误认筛选后的空结果为全局无作业。

HW-03：同一列表行只出现一次提交状态。截止信息不重复“已提交”；普通行优先标题、课程、截止与状态，教师进入详情。助教课程仍显式保留角色提示，不能误导为本人待交。

HW-04：零计数不使用危险色；仅加载完成的数据展示计数。作业全部提交、当前筛选为空、来源未完整读取必须是不同文案。不能把逾期自动当作已提交或已完成。

### 5.4 图书馆：三个并列任务

LIB-01：页面上方紧凑提供找座位、找书、本人借阅。有效预约优先展示；余量统计服务于找座位，不能替代入口。馆藏检索不再隶属于座位预约流程。

LIB-02：预约分为有效、历史、待核实。取消/结束/过期属于历史；未知状态保留原业务文字和待核实表达，不按成功处理。优先使用类型化状态；若当前只有状态文字，先明确映射与未知兜底，避免页面自行扩大字符串猜测。

LIB-03：状态图标、文字、颜色一致；取消记录不使用成功图标与成功色。有效预约无记录时提示“当前没有有效预约”；有未知记录时不能宣称“没有预约”。

LIB-04：本人借阅首次进入显示“尚未读取借阅记录”与“读取借阅记录”按钮。工具栏动作的可访问名称也应区分读取/刷新；有结果后刷新，失败就地重试。

LIB-05：借阅临时查看规则保留一条清楚摘要：“仅临时查看，离开页面或进入后台后清除”；详细规则放说明。清除后返回首次读取状态，不悄悄再次请求。保持不落磁盘、不新增续借/到期提醒的现有边界。

### 5.5 更多、账号与设置

MORE-01：更多提供直接可输入的本地服务搜索；复用既有别名检索与结果逻辑。检索对象为本机服务目录，不能暗示在学校业务数据中搜索。键盘出现后结果可滚动、可返回。

MORE-02：常用服务单项为左对齐普通列表行；多项采用一致的紧凑布局。编辑只保留一个入口，保存前后位置一致；演示偏好不写入真实账号。

MORE-03：分组名称服务于任务理解，分组内保持稳定排序；置顶迁移后不出现空分组标题。账号与设置始终可发现，内部按账号、外观/通知、数据/隐私、诊断组织。

MORE-04：退出、清除凭据、清除缓存、清除本机记录明确区分，不用一个“重置”包办。此轮界面重排不得改变数据清理边界。

### 5.6 其余页面与对象的统一约束

| 页面族 | 首要信息 | 简化方式 | 必须保留 |
| --- | --- | --- | --- |
| 成绩、研究生教务、博雅 | 选择范围、可信统计、明细 | 有价值的摘要用紧凑行/网格；移走重复解释 | 统计口径、未知值、课程角色与业务拒绝 |
| 研讨室、空教室 | 查询范围、有效结果、可执行下一步 | 查询控件同组；详情元数据只展示一次 | 有效时段、用途/人数要求、审批、待核实保护 |
| 待办、SPOC 学习 | 本机任务或学校内容及其来源 | 减少重复状态；长列表复用现有窗口组件 | 本机完成不等于学校提交；不恢复作业加入待办入口 |
| 校园卡、门锁码 | 是否已读取、敏感值及有效范围 | 默认遮挡；隐私摘要一处 | 主动读取、隐藏/显示标签、离页及后台清理 |
| 通知、就业、学术文化、校车 | 来源、日期/查询范围、内容 | 列表优先；详细口径进入详情 | 分页范围、原文入口、计划班次不等于实时余票 |
| 登录、诊断、更新、偏好 | 当前状态、下一步、结果 | 避免为统一样式增加指标卡 | 错误分类、取消路径、权限后果与真实平台支持 |

表内规则覆盖列表行、摘要、徽标、分隔线、空态、弹层、页脚与按钮；不能只优化页面外壳。具体页面基线见逐页审计，实施时只重审受影响页面及共享消费者，不重复制造“已全部验收”的结论。

## 6. 组件与视觉契约

CMP-01 信息层级：页面标题 → 用户任务/分区 → 记录主信息 → 状态和辅助属性 → 来源。每条记录主要动作明确；普通数据用主文字色，辅助信息用次级色，危险/警告色只表达实际状态。

CMP-02 几何：复用 `design/tokens/` 和既有 `AppleSection`、`AppleListTile`、`SummaryStrip`、`StatusChip`。分组沿用当前 16dp token；减少空白从重复段落、无意义分组间距着手，不缩小 Android 48dp 触控区，不新增装饰性阴影和玻璃样式。

CMP-03 标题与工具：一级页保留可收起的大标题；详情沿用紧凑导航。减轻刷新按钮底座和阴影，保证文字/图标对比与触控区。加载过程中按钮有明确忙状态，重复读取合流或排队，不静默吞掉明确刷新。

CMP-04 状态：文字必须可理解，公共状态组件沿用图标及语义色；不靠颜色单独表达。数据数值、未知占位和状态不能共用成功绿。单行内避免状态词、徽标、页脚三重重复。

CMP-05 摘要：只显示已确认且对判断有价值的信息。单项优先行，多项根据可用宽度选择并排/纵排；不为每个页面强加摘要。关键数值、状态、异常在大字号下允许换行，不能用省略号藏掉。

CMP-06 动效：保留流畅反馈、减少突然跳动，尊重减少动态效果；无等待价值的动画不阻塞导航或操作。焦点、键盘、读屏顺序与视觉顺序相符。

| 选择任务 | 首选交互 | 避免 |
| --- | --- | --- |
| 相邻日期、当前周浏览 | 页内日期条、前后切换、回本周 | 每次切一天都弹模态框 |
| 学期、课程、场馆等离散选择 | 带选中标记的列表/菜单；多项支持搜索 | 仅凭数量强制滚轮 |
| 连续日期、时间或有序周次 | 系统日期/时间控件，或经实测的滚轮/列表 | 选择后生效时机不清楚 |
| 取消、放弃编辑等动作选择 | 操作表或适当确认对话框 | 用普通筛选交互执行危险操作 |

选择器必须明确即时生效或确认生效；取消不得提交未确认选择。短菜单与滚轮的选择依语义和大字号实际表现决定，不写固定“8 项”分类规则。

## 7. 数据与交互状态契约

| 状态 | 可见表现与动作 | 禁止行为 |
| --- | --- | --- |
| 尚未读取 | 明确状态；需要主动读取的页面给文字按钮 | 显示为 0、无记录、成功 |
| 首次加载 | 当前区域加载；其他已可用内容继续操作 | 整页阻塞、反复触发请求 |
| 刷新中且有旧值 | 保留内容并表达正在更新 | 清空列表造成闪烁 |
| 成功有值 | 展示结果与可用来源/原成功时间 | 伪造时间、能力或实时性 |
| 成功为空 | 指明范围；按页面决定隐藏分区或展示空态 | 把筛选空解释为所有来源为空 |
| 失败且无旧值 | 原区域说明原因与重试 | 伪装成功空、无解释隐藏 |
| 失败且有旧值 | 保留旧结果，标记可能过期及原成功时间 | 更新成功时间或延长 TTL |
| 部分成功 | 成功内容可用；明确失败来源及覆盖不完整 | 宣称全部完成或全部已同步 |
| 模块认证失败 | 说明该服务需验证；其他模块保持可用 | 一律清空全局会话 |
| 写入结果未知 | 待核实持续可见；只允许回查 | 自动重发、隐藏风险、显示成功 |
| 账号/服务切换 | 按现有代次隔离状态，丢弃迟到结果 | 混入旧账号内容和偏好 |

查询、读取、刷新、重试均为读动作，但名称应匹配阶段；学校提交必须有独立文案、确认和状态机。使用偏好不改变缓存安全边界、匿名读取隔离或后台策略。

## 8. 首屏预算与验收场景

以下是本项目验收起始值，不是 Apple 官方要求。使用合成数据、固定学校日期及明确状态，记录画布、缩放、主题和数据条件；不能只挑信息最少的截图。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 约 390×844dp 常规字号，作业列表有结果 | 主筛选和第一条作业无需滚动可见；课程范围配置无独立大卡；同条状态仅一处 |
| AC-02 | 同画布，今天有课程、待签到及考试 | 首屏能看到课程焦点/可靠状态；签到无需穿过完整考试列表才能发现；无新增重复聚合块 |
| AC-03 | 更多 → 本人借阅，尚未读取 | 内容区文字按钮可读可点；点击一次开始读取；离页清除后返回可再次主动读取 |
| AC-04 | 图书馆同时含使用中、已取消、未知预约 | 当前有效区无取消记录；历史与未知可达；未知无成功色、不丢失 |
| AC-05 | 课表进入课程、签到，再取消/返回 | 回到正确来源并保留选择；没有学校写请求；无法关联不会误报无需签到 |
| AC-06 | 更多搜索、常用编辑、账号与设置 | 搜索可直接输入；目录置顶无重复；设置容易找到；键盘不遮住唯一动作 |
| AC-07 | 320dp、1.6×字号，浅/深色 | 内容可滚动；关键状态、时间、动作不裁切；48dp 触控不缩水；不强求常规首屏条数 |
| AC-08 | 3.2×字号专项、减少动态效果、TalkBack | 关键动作可达，读屏标签和顺序正确；不依赖颜色或动画；截图不替代实际读屏 |
| AC-09 | 无值失败、有值刷新失败、部分成功、旧日期课表 | 明确各自状态与下一步；旧成功时间不变化；不造 0 或“全部无事项” |
| AC-10 | 返回、切标签、后台恢复、账号切换、迟到响应 | 路由/滚动合理；敏感内容清除；旧响应不回写新账号；无意外重复提交 |
| AC-11 | 长标题、无时间作业、助教课程、空筛选结果 | 长文可读；未知不造时间；角色提示可见；能清除筛选返回列表 |

首屏预算不以减字号、压触控区或截断重要信息达成。常规布局失败先减少重复和配置区重量；辅助字号优先完整可达。

## 10. Harness 执行与交付协议

1. 读取 AGENTS、UI-DESIGN、本设计、当前 TODO 与相关接口索引；盘点分支、脏工作树和上一批证据。明确本批需求编号及受影响共享消费者，不重做已验收默认矩阵。
2. 用合成数据复现本批问题，记录实际操作、预期、实际和截图。区分当前代码事实、旧版意见、设计建议与协议待验证；没有证据不补造学校行为。
3. 优先复用已有组件、状态机和 gateway；页面不解析学校 JSON、不接 token、不新增学校请求。共享组件修改检查其他页面、深浅色、窄屏与辅助字号。
4. 同步本批涉及的 UI 准则与静态门禁。读取空态按钮等允许场景应精确识别；避免用宽泛豁免绕过刷新规则。文案检查不能代替状态行为回归。
5. 为有行为风险的变化补必要回归：首次读取/去重、预约未知映射、取消无提交、账号隔离、失败保留。纯装饰调整不为测试数量添加机械断言。
6. UI 实现后运行适用页面/组件测试与 `bash scripts/check-mirror.sh`。在隔离 Android 模拟器复走本批任务；共享变化复拍受影响矩阵，查看实际图像。全量页面变化才使用全页面脚本。
7. 设备集成后重建正常 `main.dart` 入口 Debug APK；`git diff --check` 收尾。Windows 验收在 Windows 主机/CI，TalkBack 在可操作环境实际验证；缺少证据保留未验收。
8. 更新现有 TODO 对应状态与既有审计/按日期新增证据记录，引用需求和 AC 编号；报告改了什么、为什么、验证了什么、剩余什么。不得把设计完成写成实现完成，把模拟器合成通过写成真实账号/真实写入验收。

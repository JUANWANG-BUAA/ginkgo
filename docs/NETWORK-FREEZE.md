# 网络与认证冻结

## 冻结基线

2026-11-03，用户安装本轮交付后明确反馈：“登录成功了”，并要求冻结网络部分，避免后续 agent 再次改坏。

- 产品基线：Android Beta.9，`0.1.0-beta.9+19`。
- 不可移动的源码参考：`c4afc0c3f5edad5cded1352da5b536001edb430a`，标签 `android-v0.1.0-beta.9`。
- 本次现场反馈承接 Beta.8 “仅 WebVPN + 验证码”失败的修复链，关闭该次登录阻断；没有要求用户再次登录或提供敏感信息。
- 这是用户报告的登录成功，不等同于全部路线、冷恢复、业务模块、覆盖升级、学校写入或安全审查均已验收。发布 readiness 仍为 blocked，不据此批量改写验收项。
- 构建、严格请求转录、故障变体及公开包证据见 [发布记录](_audit/2026-11-03-beta9-publication.md)；历史参考 UBAA `e8a397fc`、Beta.3 `32b6a1d6` 不得替代这个已可用的产品基线。

## 冻结范围

冻结的是行为，不只是几个文件：共享 HTTP 客户端配置和依赖、TLS/代理/UA/协商头/压缩/超时/取消；CAS、验证码取页与 execution、字段与编码、到期确认、跳转及服务票据消费；UC 身份确认与账号一致性；Cookie 作用域、插入/轮换及持久化；直连/WebVPN 与 Automatic；会话恢复、退出、保险库、冷却和密码单次提交。

Rust 的 auth、共享网络 foundation、reqwest transport、session service、桥接认证入口，以及对应严格测试、参考向量和验证器由 `network-freeze.json` 的路径/哈希清单保护。网络依赖清单和锁文件也冻结，避免“升级依赖”暗改运行行为。保护目录内新建源文件同样会被门禁检出。

Flutter 登录编排、平台配置、runtime 组装以及其他业务模块即使不在逐字节清单内，也不得绕开上述行为约束。普通 UI 和业务开发可以继续，但只能复用现有网络端口，不得因单模块错误修改全局会话、自动补交密码或建立第二套传输实现。冻结不要求把所有业务解析器或整个 Flutter 服务文件锁死。

## 修改规则

1. 默认只读。重构、清理、优化、提高一致性、对齐 UBAA、修复别的功能、全量审查或“继续开发”都不构成解冻授权。
2. 发现缺陷或安全风险，先向用户报告具体证据、冻结文件和行为影响，等待用户明确授权这个具体修改；不得自行以“安全修复”为由越过冻结。
3. 获准后仅解冻最小范围，以 Beta.9 保留回退点，先写能抓住旧错误的严格回归，不改独立参考预期来迎合实现，不做猜测性网络改动。
4. 执行相应离线回归、完整镜像门禁、正常入口构建；真实账号仅由用户另行授权并控制次数。最终是否继续冻结及采用哪个新基线由用户决定。
5. `network-freeze.json`、检查器、CI 接线及本规则同属保护机制。不得自动更新哈希、移动标签、缩小路径范围、跳过门禁或将格式化差异视为无须授权。没有自动 refresh/bypass 开关。

## 门禁

### 2026-11-03 最小授权例外

用户在报告“几分钟后重新要求登录、后台无提醒”并确认修复范围后回复“好的，开始”，授权后台提醒调度和冷启动恢复失败处理。仅 `session_source.rs` 的快照读取错误由吞错改为向上传递；CAS、验证码、密码提交、Cookie、路线与 HTTP 实现仍保持 Beta.9 原字节。原始清单哈希保留不动，`authorized_revisions` 只允许检查器内逐字固定的这一个修订哈希，不提供通用刷新或绕过。Android 保险库读取失败不再冒充“无记录”，Flutter 暂时故障展示重试而不是退出；后台新入口使用密码盲、仅内存的会话副本，不改交互登录链。范围及验证见[本轮记录](_audit/2026-11-03-background-reminders-and-recovery.md)。后续不得以此例外继续修改其他冻结行为。

`python3 scripts/check-network-freeze.py` 无网络、无账号、无需历史 Git 对象，逐文件比较固定 Beta.9 清单；新增、删除、改动或符号链接均失败。完整本地门禁和 Mirror CI 在开始时执行它，并运行检查器自己的反例测试。

这是防止误改和明确代理权限的仓库约束，不是不可绕过的访问控制；有仓库写权限的人仍能改门禁。后续 agent 必须遵守用户授权规则，不得以这种技术限制为理由自行解冻。

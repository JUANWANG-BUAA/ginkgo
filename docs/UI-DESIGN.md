# BUAA Assistant — macOS 原生 UI 设计准则

> 状态：v1 设计基线，2026-10-15。适用范围：macOS 14+ 的主窗口、菜单栏面板、登录、课表、提醒、成绩、图书馆及设置。本文指导实现和验收；当前已接入主要页面，以下目标不等于全部实现，具体范围见 IMPLEMENTATION.md。
>
> **规范优先级**：Apple 平台行为与系统组件 > 本文的产品规则 > `ARCHITECTURE.md` §10 的历史视觉草案。本文中的尺寸与阈值若未标为 Apple 官方要求，均为本项目起始值，需通过真机、窗口缩放和辅助功能验收调整。

## 1. 产品定位与设计目标

BUAA Assistant 是一个“打开即知道今天需要关注什么”的个人校园工作台。它的优势是 macOS 原生的快速查看、键盘操作、菜单栏访问与系统通知，不是把所有校园网页缩进一个窗口。

设计优先级从高到低：

1. **可信**：区分“没有待办”和“尚未查到”；每个动态状态都能看到数据来源、最后成功同步时间及异常。
2. **及时**：课前提醒和已发现的待处理事项容易看到；不承诺本地离线时能发现临时签到。
3. **快速**：菜单栏承担 5–10 秒内完成的查看或跳转，复杂浏览留给主窗口。
4. **克制**：优先系统控件和清楚的文字层级，不用装饰性玻璃、渐变或持续动画制造“原生感”。
5. **安全**：登录凭据与他人信息不在不必要的界面、通知或日志中暴露；写操作必须有明确的用户意图。

## 2. 信息架构

| 表面 | 核心任务 | 首屏内容 | 不放什么 |
|---|---|---|---|
| 菜单栏面板 | 一眼确认今天是否有事 | 监测状态、下一节课、最近一件待处理事项、打开主窗口 | 全学期课表、长列表、成绩明细、复杂表单 |
| 主窗口「今天」 | 汇总接下来要做的事 | 时间线、待处理事项、最近同步、异常提示 | 与侧边栏重复的大量导航卡片 |
| 主窗口「课表」 | 查某周课程 | 周切换、当日定位、课程详情 | GPA、跨系统设置 |
| 主窗口「成绩」 | 查成绩与趋势 | 学期选择、成绩列表、统计口径 | 与原始上游字段同名的技术数据 |
| 主窗口「图书馆」 | 查可用资源 | 座位/预约状态，随后再扩展借阅 | 没有验证过的借阅入口 |
| 设置 | 管理账户与提醒 | 账号、通知、启动、数据与隐私、诊断 | 日常业务操作 |

「今天」建议作为登录后的默认页，当前侧边栏顺序为“今天 / 课表 / 成绩 / 图书馆 / 空教室 / 待办 / 设置”。签到状态、希冀作业等经过协议验证后，先作为「今天」的事项来源；内容足够复杂时再升级为独立页面。尚未接入的功能不要占据正式导航位。

## 3. 窗口和导航

- 主窗口使用 `NavigationSplitView`、系统侧边栏、原生工具栏与标准窗口控件。用户可以调整窗口大小、隐藏侧边栏；窄窗口下内容应自适应，不能裁切关键按钮。[Apple：Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)。
- 当前工程的 **800 × 560 pt 是项目初始最小窗口尺寸**，不是 HIG 规定。若登录、空态等页面可在更小尺寸工作，可以按实测放宽；不要硬编码标题栏或交通灯按钮尺寸。
- 工具栏只放当前页高频操作，例如刷新、选择学期、切换周；刷新操作还应在菜单命令中可用。容纳不下时让系统处理溢出，不自行画第二套工具栏。[Apple：Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)。
- 菜单栏面板当前宽 **360 pt 为项目起始值**。优先让内容自然增高；当待办超过三条时显示“查看全部”，避免面板变成滚动主应用。面板关闭再打开时保持合理的今日状态，不把“已连接”图标等同于“数据刚刚查过”。
- “打开主窗口”应恢复已有窗口、定位到相关事项，而不是意外创建重复窗口。点击提醒后也遵守同一导航路径。
- 支持常用键盘命令：`⌘R` 刷新当前页、`⌘,` 打开设置；只有在不与系统或其他应用冲突且用户可关闭时才提供全局快捷键。所有主要动作须可通过键盘完成。

## 4. 页面规格

### 4.1 登录

- 一个明确的主动作“登录”，学号、密码与动态出现的验证码采用系统表单控件；登录中禁止重复提交，取消/失败后保留可安全重试的输入状态。
- 错误提示贴近表单，分开说明“凭据错误”“需要验证码”“网络不可用”“服务暂不可用”；不要把所有失败显示成“密码错误”。
- 密码默认不可见，界面不显示完整 Cookie、Token 或调试响应。会话失效时保留可用缓存，并明确标注“需要重新登录才能刷新”。
- 登录前不请求通知权限；在用户打开提醒功能时解释用途后再调用系统权限请求。

### 4.2 今天

- 顶部先显示一句可行动的摘要，例如“下一节课 14:00 · 新主楼”，或“有 1 件事项待处理”。如果同步失败，只能说“暂时无法确认是否有新事项”，不能显示“今天无待办”。
- 主体按时间排序：正在进行 → 即将开始 → 今天稍后 → 已完成。已过期事项收起或移入历史；同一事项不可重复出现多次。
- 每条事项展示标题、时间/期限、来源、状态、主要动作。来源可以是课表、签到状态、作业等；未知状态用文字说明，不用单个颜色或圆点猜测。
- 点击签到事项首先打开详情或上游网页；未来的一键签到属于独立审查的写操作，不能由提醒点击直接代为提交。

### 4.3 课表

- 周切换、回到本周、日期范围始终可见；课程卡片显示名称、起止节次/时间、地点，并在详情呈现教师等次要信息。
- 同时保留周视图与今日列表的语义：周视图用于规划，菜单栏与「今天」只展示即将发生的课程。课程重叠时不得覆盖或隐藏其中一门。
- 缓存课表可先显示，但须标记“上次更新”并在后台刷新；空课表、当前周无课和刷新失败是三种不同状态。

### 4.4 成绩与图书馆

- 成绩页把原始成绩与计算出的 GPA 明确分开，并说明学期、算法和未计入项；成绩未发布时不要用 0 分或空白误导。
- 图书馆页先做已验证的座位链路；预约/取消需要可辨认的确认动作。提交后若网络超时，显示“结果待核实”，先查上游状态，不自动重发写请求。
- 未验证协议的“借阅”“签到提交”等入口不得以可点击的正式功能形态出现。

## 5. 状态语言：每个数据模块都必须有

| 状态 | 界面表达 | 可用操作 |
|---|---|---|
| 首次加载 | 显示系统进度指示和正在查询的服务名 | 可取消或返回，不显示伪数据 |
| 有数据且新鲜 | 正常内容；必要时显示最近同步时间 | 查看、手动刷新 |
| 有缓存但刷新失败 | 保留旧内容，明确“更新失败 · 数据截至…” | 重试、打开上游 |
| 成功查询后确实为空 | 写清范围，如“本周没有课程” | 切换周/学期 |
| 未登录/会话过期 | 区分“需重新登录”与上游故障 | 登录；保留非敏感缓存 |
| 上游不可用 | 说明是哪项服务受影响，不将全部应用判为离线 | 重试、查看其他模块 |
| 监测不可用 | “未能确认是否有新签到”，记录最后成功检查 | 手动检查、打开上游 |

**项目起始阈值（待实测）**：动态签到状态若超过预定轮询周期的两倍仍未成功检查，就标成“监测可能滞后”；课表等低频数据按日展示上次更新时间。阈值应由各数据源配置，不写成全局常量。对任何跨服务聚合结果，必须避免把某一个来源失败误写成全局“无事项”。

## 6. 通知设计

- 首版优先做“已知课程开始前提醒”和“应用在线时发现的新待办”。这两类通知在设置中分别开关，并可调整提前量、静默时段或关闭声音。
- 本地定时通知可由系统在 App 未运行时投递，但**不能替应用发现它尚未查询到的临时任务**；Mac 关机、离线或未运行监测时不承诺实时发现。[Apple：本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)。
- 通知标题说清事项和期限，正文控制在锁屏可接受的信息量；默认不含学号、成绩数值、密码或个人敏感详情。点击通知定位到对应详情。
- 去重键由“来源 + 上游 ID + 事件类型 + 有效窗口”构成；状态变化时更新/撤销过时通知，避免刷新多次连发。
- 不用通知承载错误提示；错误放在应用内。仅对确实发生在当下、需要立刻处理的事项评估 Time Sensitive，并尊重专注模式和系统授权。[Apple：Notifications](https://developer.apple.com/design/human-interface-guidelines/notifications)、[Managing notifications](https://developer.apple.com/design/human-interface-guidelines/managing-notifications)。

## 7. 视觉与组件规则

- **系统优先**：优先 `List`、`Form`、`Button`、`Toggle`、`Picker`、`NavigationSplitView`、`MenuBarExtra`、系统 `Alert`/`Sheet`。不要用自制卡片替换所有列表，也不要用 Sheet 承载普通导航。
- **颜色**：文本和背景优先语义色；状态使用系统色并配文字/图标。自定义品牌色仅用于强调，需提供浅色、深色和高对比度变体。不要在规范中写死“系统蓝的 hex 值”。[Apple：Color](https://developer.apple.com/design/human-interface-guidelines/color)、[Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)。
- **材质**：采用系统窗口、侧边栏和控件自动提供的材质。Liquid Glass 属于导航与控件层；内容层保持清晰可读，不对每张课程卡片套自制“玻璃”修饰器。macOS 14 与较新系统由系统分别呈现，不手绘跨版本仿制。[Apple：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。
- **文字**：以 `.body`、`.headline`、`.caption` 等语义文本样式为主。学号、时间和状态不依赖过小、过淡的字；中文长课程名允许换行或在详情完整显示。固定字号仅用于有明确测试依据的特殊图形。
- **间距**：4/8/12/16/24 pt 可作为项目排版起点，不是 HIG 强制 token；先让系统控件决定尺寸。对齐、分组、留白比给每个元素加边框更重要。
- **图标**：SF Symbols 用于辅助识别，图标按钮须有可见提示或无障碍名称。菜单栏图标不宜靠细微颜色区分登录、断线、监测异常。
- **动效**：状态变化可用短暂、可中断的系统过渡；不要求“所有变化都用弹簧”。减少动态效果时关闭位移/缩放装饰性动画，进度状态仍要可理解。

## 8. 无障碍、隐私和本地化

- 所有主要流程用键盘、VoiceOver 跑通；焦点顺序与视觉顺序一致。图标按钮有准确的 `accessibilityLabel`，状态变化必要时提供公告。
- 在浅色、深色、增加对比度、降低透明度、减少动态效果及大字号设置下逐页检查。信息不只靠颜色表达，文本截断不影响完成任务。[Apple：Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)。
- 通知、菜单栏和窗口标题默认最小化个人信息；设置提供清除本地缓存和退出登录入口，操作说明具体影响。
- 文案使用“同步/检查/已发现/未确认”等准确用语；上游返回的原始错误先转成用户能理解的提示，同时提供不含敏感数据的诊断信息。
- 日期、星期、时间与数字使用系统格式，避免硬编码 12/24 小时制；界面文字留出中英文长度变化的空间。

## 9. 为未来服务端保留的 UI 接口

UI 只接收统一的事项视图模型：`id`、`source`、`title`、`timeWindow`、`status`、`lastVerifiedAt`、`availableActions`、`provenance`。这些字段为**设计契约示意**，不是已实现 Swift 类型或服务端 API。数据可来自本地直连或未来的远程监测；来源切换不改变“今天”与菜单栏的基本信息结构。

未来若接服务端，设置页须明确展示：是否启用远程监测、最近心跳、覆盖的事项类型、凭据/会话如何处理、暂停与删除方式。服务器提示也要保留“最后成功检查”的透明度；不能把“服务器已连接”当成“学校系统已经确认没有待办”。

## 当前界面与待验收项（2026-10-15）

- 登录采用双栏布局与表单状态提示；成功 toast 在根视图展示。状态提示、标题和空态由 Core/UI/PageComponents.swift 复用。
- 周课表按星期与节次对齐，横向滚动容纳窄窗口；课程按稳定颜色区分，重叠课程分栏，点击打开详情。学期总览按周展示课程与地点；本科未查询周显示“未查询”。
- 图书馆采用楼馆/分区/日期时段选择与座位网格；预约和取消均有确认弹窗。尚未完成研讨室专用分类；预约记录只显示前 100 条。
- 空教室提供楼栋概览、房间列表、节次对照和房间详情；支持校区/日期、搜索、节次、空闲数量、连续空闲筛选与排序。图书馆提供查询步骤指引及座位筛选；课表增加每日清单；待办提供逾期筛选。学校作业摘要已接入今天页，签到尚未接入。
- 已有切周、显示模式和 toast 的短暂过渡，并读取减少动态效果设置。浅色/深色、窄窗口、键盘与 VoiceOver 的完整验收尚未完成；网格表头与节次列尚未冻结。

## 10. 交付与验收清单

每做完一页，至少用正常数据、空数据、加载中、断网缓存、会话过期和上游异常六组状态验收；通知页再补权限拒绝、重复事件、过期事件。每组都在浅色/深色、窄窗口和键盘/VoiceOver 下抽查。

- [ ] 首屏能在约 5 秒内回答“现在该关注什么”，且不能把未知状态伪装为“无事”。
- [ ] 每个动态来源能看到最后成功检查时间；局部故障不会覆盖其他正常来源。
- [ ] 菜单栏面板可快速查看和跳转；主窗口可恢复到正确事项。
- [ ] 系统通知经明确授权、可分别关闭、不会因重复刷新刷屏。
- [ ] 所有写操作有清楚的对象和结果反馈；不确定结果不会自动重试。
- [ ] 真实 Mac 上验证窗口缩放、深色模式、键盘、VoiceOver、降低透明度与减少动态效果。

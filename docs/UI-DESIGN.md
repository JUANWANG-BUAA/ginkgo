# Ginkgo — UI 设计准则

## 当前 Android / Flutter 工作树补充（2026-10-26）

当前唯一开发目标是 Android；以下历史 macOS 章节仅作信息层级参考，不要求改动冻结的 Apple 应用。
Flutter 延续 iOS 式 inset grouped、语义色/字号和轻量分隔，同时遵循 Android 返回、安全区、键盘与至少 48dp 触控目标。

- 功能密度上升时先减重复说明和无效操作，不把每项元数据画成同权重卡片。
- 总览与明细分层：手机四项指标用自适应 2×2；类别/课组用紧凑文字行，未知值仍写明。
- 私密信息先呈现简短保护摘要，长实现说明可展开；危险写入确认和结果未知保护不得折叠掉。
- 页面进度/刷新/图标优先当前主题，状态语义色保留独立文字，不借绿色容量标记暗示实时可用。
- 计划时刻表、实时余票、公开馆藏与本人借阅明确区分，不用外链或成功空态冒充已接通。
- 先渲染截图，再修改布局，再复拍；普通深浅色和 320dp/1.6×/替换强调色均要看，禁止仅凭 analyze 宣称视觉验收。

本轮具体截图问题、修正与复跑入口见 [视觉及模块闭环](_audit/2026-10-26-module-integration.md)。

## 最终交互规则（2026-10-28）

以下规则以最终用户复核为准，不再沿用中间迭代的聚合时间线或折叠服务卡片：

1. **不设置近期时间线**。课程、作业和本机待办只保留原分区；考试仅在有未早于学校今天的记录时出现独立卡片，加载、失败和成功为空均不占位。
2. **服务目录保持原 iOS 分组列表**。设置、SPOC 学习、博雅、研究生教务等入口使用原有 `AppleSection`、图标行和目的地导航；搜索使用二级页面，不在工作台内嵌另一套折叠卡片或嵌套滚动。
3. **空结果不制造卡片**。没有明确事项时收起或不渲染；错误、旧缓存和权限不完整必须与确认空分开。`rolesComplete=false` 显示“作业结果不完整”，不得显示“当前没有待处理作业”。
4. **签到按操作需要去重**。同场次不同上游 ID 仅在存在未签到目标时分别显示并保留提交入口；已签到等无需操作的记录折叠为一行，同 ID 真重复折叠，冲突仍显示待确认。
5. **导航与状态一致**。服务替换或账号切换时清空旧状态并丢弃迟到响应；公共来源失败不隐藏其他来源。原生入口使用 chevron，官网入口明确标记“前往官网 ↗”，不伪装成原生能力。
6. **退出和写入不阻塞界面**。显式退出先完成本地身份、Cookie、快照和凭据清理并返回登录页，不等待上游登出或偏好磁盘写入。待办和 CGYY 的阻塞文件操作进入 `spawn_blocking`，不得持同步锁跨越 `await`。
7. **保留既有视觉语言**。新内容复用 `TodayVisualSection`、`TodayActionRow`、`AppleListTile` 和至少 48dp 触控，不另造阴影、玻璃卡片或第二套导航样式；320dp、大字号、深浅色和系统返回必须有相应回归。

# 历史：macOS 原生 UI 设计准则

> 状态：v1 设计基线，2026-10-15。适用范围：macOS 14+ 的主窗口、菜单栏面板、登录、课表、提醒、成绩、图书馆及设置。本文指导实现和验收；当前已接入主要页面，以下目标不等于全部实现，具体范围见 IMPLEMENTATION.md。
>
> **规范优先级**：Apple 平台行为与系统组件 > 本文的产品规则 > `ARCHITECTURE.md` §10 的历史视觉草案。本文中的尺寸与阈值若未标为 Apple 官方要求，均为本项目起始值，需通过真机、窗口缩放和辅助功能验收调整。

## 1. 产品定位与设计目标

Ginkgo 是一个“打开即知道今天需要关注什么”的个人校园工作台。它的优势是 macOS 原生的快速查看、键盘操作、菜单栏访问与系统通知，不是把所有校园网页缩进一个窗口。

设计优先级从高到低：

1. **可信**：区分“没有待办”和“尚未查到”；每个动态状态都能看到数据来源、最后成功同步时间及异常。
2. **及时**：课前提醒和已发现的待处理事项容易看到；不承诺本地离线时能发现临时签到。
3. **快速**：菜单栏承担 5–10 秒内完成的查看或跳转，复杂浏览留给主窗口。
4. **克制**：优先系统控件和清楚的文字层级，不用装饰性玻璃、渐变或持续动画制造“原生感”。
5. **安全**：登录凭据与他人信息不在不必要的界面、通知或日志中暴露；写操作必须有明确的用户意图。

## 2. 信息架构

| 表面 | 核心任务 | 首屏内容 | 不放什么 |
|---|---|---|---|
| 菜单栏面板 | 一眼确认今天是否有事 | 监测状态、下一节课、最近一件待处理事项、打开主窗口 | 全学期课表、长列表、成绩明细、复杂表单 |
| 主窗口「今天」 | 汇总接下来要做的事 | 时间线、待处理事项、最近同步、异常提示 | 与侧边栏重复的大量导航卡片 |
| 主窗口「课表」 | 查某周课程 | 周切换、当日定位、课程详情 | GPA、跨系统设置 |
| 主窗口「成绩」 | 查成绩与趋势 | 学期选择、成绩列表、统计口径 | 与原始上游字段同名的技术数据 |
| 主窗口「图书馆」 | 查可用资源 | 座位/预约状态，随后再扩展借阅 | 没有验证过的借阅入口 |
| 设置 | 管理账户与提醒 | 账号、通知、启动、数据与隐私、诊断 | 日常业务操作 |

设置页的“启动”区提供用户主动控制的登录项开关。开关状态以 macOS Service Management 为准；系统要求批准时，页面说明下一步并提供打开登录项设置的操作，不把“已注册”显示成“已获批准”。

「今天」作为登录后的默认页。当前侧边栏分为“工作台”（今天、课程签到）、“学习”（课表、成绩、作业）和“校园”（图书馆、空教室、待办），设置固定在底部；账号名与连接状态合并放在品牌区，避免重复占据导航空间。当前页同时以柔和底色、强调文字和窄侧边标记识别；悬停提供轻量反馈，页面切换使用短暂淡入/位移，遵循系统“减少动态效果”设置。课程签到、学校作业和个人待办可以显示紧凑状态徽标：作业徽标只突出未来 24 小时内截止的待处理项；已逾期或远期未做作业不使用紧急徽标，部分来源未更新时显示“+”或“!”。未知或查询失败明确显示未确认，不把加载中解释成零。徽标出现与变化有短暂过渡，选中标记在页面间平滑移动。分组标题、导航行与底部设置保持清楚间距，窄侧栏时标题不换行且不依赖图标单独传达含义。签到状态与签到提交使用独立页面；提交需逐课程确认，完成后回查状态。实际成功写入尚未在真实课程中验收，不得将协议接入等同于写入已验证。

## 3. 窗口和导航

- 主窗口使用 `NavigationSplitView`、系统侧边栏、原生工具栏与标准窗口控件。用户可以调整窗口大小、隐藏侧边栏；窄窗口下内容应自适应，不能裁切关键按钮。[Apple：Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)。
- 主窗口默认尺寸为 **1200 × 800 pt**，项目最小值为 **800 × 560 pt**。默认值为当前产品选择，不是 HIG 要求；窗口在当前显示器工作区不足时由系统调整。
- 当前工程的 **800 × 560 pt 是项目初始最小窗口尺寸**，不是 HIG 规定。若登录、空态等页面可在更小尺寸工作，可以按实测放宽；不要硬编码标题栏或交通灯按钮尺寸。
- 工具栏只放当前页高频操作，例如刷新、选择学期、切换周；刷新操作还应在菜单命令中可用。容纳不下时让系统处理溢出，不自行画第二套工具栏。[Apple：Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)。
- 菜单栏面板当前宽 **360 pt 为项目起始值**。优先让内容自然增高；当待办超过三条时显示“查看全部”，避免面板变成滚动主应用。面板关闭再打开时保持合理的今日状态，不把“已连接”图标等同于“数据刚刚查过”。
- “打开主窗口”应恢复已有窗口、定位到相关事项，而不是意外创建重复窗口。点击提醒后也遵守同一导航路径。
- 支持常用键盘命令：`⌘R` 刷新当前页、`⌘,` 打开设置；只有在不与系统或其他应用冲突且用户可关闭时才提供全局快捷键。所有主要动作须可通过键盘完成。

## 4. 页面规格

### 4.1 登录

- 一个明确的主动作“登录”，学号、密码与动态出现的验证码采用系统表单控件；登录中禁止重复提交，取消/失败后保留可安全重试的输入状态。
- 错误提示贴近表单，分开说明“凭据错误”“需要验证码”“网络不可用”“服务暂不可用”；不要把所有失败显示成“密码错误”。
- 密码默认不可见，界面不显示完整 Cookie、Token 或调试响应。会话失效时保留可用缓存，并明确标注“需要重新登录才能刷新”。
- 登录前不请求通知权限；在用户打开提醒功能时解释用途后再调用系统权限请求。

### 4.2 今天

- 顶部先显示一句可行动的摘要，例如“下一节课 14:00 · 新主楼”，或“有 1 件事项待处理”。如果同步失败，只能说“暂时无法确认是否有新事项”，不能显示“今天无待办”。
- 主体按时间排序：正在进行 → 即将开始 → 今天稍后 → 已完成。已过期事项收起或移入历史；同一事项不可重复出现多次。
- 每条事项展示标题、时间/期限、来源、状态、主要动作。来源可以是课表、签到状态、作业等；未知状态用文字说明，不用单个颜色或圆点猜测。
- 点击签到事项首先打开详情或上游网页；未来的一键签到属于独立审查的写操作，不能由提醒点击直接代为提交。

### 4.3 课表

- 周切换、回到本周、日期范围始终可见；课程卡片显示名称、起止节次/时间、地点，并在详情呈现教师等次要信息。
- 同时保留周视图与今日列表的语义：周视图用于规划，菜单栏与「今天」只展示即将发生的课程。课程重叠时不得覆盖或隐藏其中一门。
- 同日、同课程、同教室且节次连续的记录合并为一张卡；教师字段不一致时保留在详情里，不因此拆开课程卡。周网格保持易读的列宽，不为强行同屏缩小卡片，窄窗口允许横向滚动。
- 缓存课表可先显示，但须标记“上次更新”并在后台刷新；空课表、当前周无课和刷新失败是三种不同状态。
- 本科课表增加“考试安排”视图；考试卡片按时间排序，日期作为视觉锚点，考场/座位为次级但清晰可扫读信息。首次加载、确认无考试、刷新失败各自表达，失败时保留旧结果并允许立即重试；研究生门户不展示该入口。切换和结果出现采用短时淡入，尊重“减少动态效果”。
- 教务页共用克制的页面标题与 section heading；学期/周次控件归为一组，数据更新时间作为次级信息。周课表保留课程卡片以表达时间块，不把课程网格改成通用仪表盘卡片。

### 4.4 成绩与图书馆

- 成绩页先呈现学期选择与最近同步时间，再呈现课程数、加权平均分和参考绩点；统计与原始课程成绩分区展示。成绩列表按课程、学分、成绩对齐，搜索和分页不改变学期统计口径。详细算法、适用范围与未计入项收在可展开的“统计口径”说明中；成绩未发布时不要用 0 分或空白误导。
- 图书馆页先展示官网明确提供的校区在馆人数与可用空间统计，再提供当前时段座位链路；人数、可预约座位、研讨间、寄存柜需有清楚的文字语义。预约仅使用今天正在开放的时段。大列表按条目分页；预约已结束或取消时保留历史信息但不显示取消动作。预约/取消需要可辨认的确认动作。提交后若网络超时，显示“结果待核实”，先查上游状态，不自动重发写请求。
- “我的预约”分成“进行中的预约”和“历史记录”，同一记录不重复出现。只有上游明确返回 `flag_in/flag_out/flag_leave/oksign` 时才显示签到入座、临时离开、完全离开、取消预约；文案必须区分“临时离开保留座位”和“完全离开结束使用”，两种离开与签到都需二次确认。写操作后刷新当前记录，结果不确定只提示待核实，绝不自动重发。
- 未验证协议的“借阅”等入口不得以可点击的正式功能形态出现。签到提交入口仅在明确说明对象、二次确认及回查逻辑后开放；学校结果未确认时不能显示成功。

### 4.5 空教室

- 查询范围是首要层级：校区、日期与“今天/明天”快捷项同组；“查询空教室”为唯一主操作，“强制刷新”作为跳过短时缓存的次操作。
- 查询结果中的搜索框保持可见并即时筛选；节次、最少空闲节数、连续空闲与排序收在“筛选与排序”折叠区。折叠标题显示活动条件数量；筛选导致零匹配时自动展开，方便直接修正条件。
- 楼栋概览、房间列表和节次对照属于结果布局，不与筛选条件混放。房间行展示空闲节数和连续长度，详情按 1–14 节说明“空闲/未标为空闲”，并提示数据不是预订或占用保证。
- 搜索匹配忽略房间名中的空格、括号等展示标点，例如“(三)105”可由“三105”找到。清除操作恢复全部当前查询结果，不应重新请求学校服务。

### 4.6 学校作业

- 作业列表行先呈现标题与状态，再显示课程/来源和发布时间、截止时间；紧迫度用文字说明，缺失字段标成“未确认”。SPOC 可在应用内打开详情，列出教师、提交状态、发布时间、截止时间、作业分值、提交时间和文字要求；希冀详情呈现总体进度及题目级提交/得分。满分与个人得分分字段显示，不能混称。
- 未知提交状态保留“待确认”语义；若来源提供原始状态文本，作为次级说明展示并限长，不用原始值覆盖规范状态或筛选结果。
- 顶部状态计数作为筛选快捷入口，与状态分段控件同步；选中状态使用轻量强调底色，计数、搜索、来源筛选和结果列表形成连续层级，不为每条作业重复绘制独立卡片。数字变化可短暂过渡，并遵循减少动态效果设置。
- 显示来源级学期上下文时，加载或刷新失败必须标明“上次”，不能让缓存学期看起来像当前刚核验的结果。
- 详情加载中、详情读取失败与正文为空是三种不同状态；读取失败保留摘要并可重试，空正文提示回上游检查附件或复杂格式。希冀详情/提交仍在原站点完成时，明确提供打开原页面的操作；SPOC 当前提供站点级回退入口，不将其误称为作业深链。
- Judge/SPOC 任一来源失败时显示部分结果告警；未成功同步的来源不得计作零项。所有提交功能都必须在取得端点证据后再实现，显示明确提交对象，用户确认后只发一次；超时先回查状态，不能盲目重发。

签到状态回查后可对状态徽标和计数做短时过渡，刷新中使用明确的进度指示；签到中的按钮保留独立键盘/VoiceOver 焦点并说明正在等待学校结果；非必要动效尊重“减少动态效果”。

### 4.7 研讨室（教学楼 CGYY）

- 页面分“预约 / 我的预约 / 门锁密码”三档。预约页先选校区、楼栋/场地和日期，再用“空间 × 时段”卡片选择；同一个空间可多选时段，不同空间不能混在一次预约里。
- 预约表单包含手机号、活动主题、活动类型、参与人数、活动内容、参与人说明与两个安全选项。提交前二次确认；滑块验证码由用户明确授权后自动识别，失败只提示重试，不自动重发订单。
- 我的预约显示审批状态、场地、时间与取消入口；取消需二次确认。门锁密码独立成页，显示密码/二维码、有效期、场地与时段，并明确提示不要转发或截图分享。
- 图书馆 `v4/seminar` 只读空档代码已随 2026-10-19 瘦身删除；“研讨室”只指教学楼 CGYY，图书馆仅提供座位预约。

### 4.8 研究生教务与博雅

- 研究生教务按“学分地图 / 课程与原文 / 成绩与考试 / 学籍信息”组织。总览分别显示方案要求、学校认定、本学期在修和缺口；进度条用不同颜色显示已认定、在修、待考核和其余要求，学期不明或课程学分未知时标注待核对。
- 学分地图按类别 → 课组 → 课程展开，层级直接显示要求、已获、在修和缺口；执行报告无法归类的在修课独立展示。方案课程池、成绩和长要求列表折叠并分页，不把课程池当待修清单。成绩未通过、执行报告待考核和课表在修分开着色。
- 学籍信息只显示真实可用的学籍摘要，并链接回学校平台办理其他事项；不展示无法办理的应用目录。0 条成绩显示“教务系统当前返回 0 条”，不显示成接口不可用。
- 博雅按“概览 → 课程库/已选课程/完成统计”组织。课程卡片展示名称、类别、教师、地点、人数和校区；详情补充选课窗口、退选截止、课程简介与签到配置。统计用“已完成/应完成 + 进度条”，0/0 明确说明当前学期没有要求。
- 两页都是只读：选课、退选、签到、评教和培养环节提交不出现可点击的正式入口。
- 博雅概览的课程数、已选数、有效数和学期信息使用单一摘要条；个人/学期上下文作为次级信息。课程库的搜索与类别筛选和课程网格分组，但不把包含课程卡片的整个结果区域再套入第二层卡片。

## 5. 状态语言：每个数据模块都必须有

| 状态 | 界面表达 | 可用操作 |
|---|---|---|
| 首次加载 | 显示系统进度指示和正在查询的服务名 | 可取消或返回，不显示伪数据 |
| 有数据且新鲜 | 正常内容；必要时显示最近同步时间 | 查看、手动刷新 |
| 有缓存但刷新失败 | 保留旧内容，明确“更新失败 · 数据截至…” | 重试、打开上游 |
| 成功查询后确实为空 | 写清范围，如“本周没有课程” | 切换周/学期 |
| 未登录/会话过期 | 区分“需重新登录”与上游故障 | 登录；保留非敏感缓存 |
| 上游不可用 | 说明是哪项服务受影响，不将全部应用判为离线 | 重试、查看其他模块 |
| 监测不可用 | “未能确认是否有新签到”，记录最后成功检查 | 手动检查、打开上游 |

页面模型由主窗口持有，切换侧栏页面时继续显示已有数据；新窗口优先恢复本机快照，再刷新学校服务。考试和空教室结果要显示上次查询时间；校园通知缓存最多显示 5 条。签到缓存标明“缓存状态”，联网核对前不提供签到提交；历史日期缓存命中时保留记录并并行显示更新进度。空教室按账号缓存最近 12 组校区/日期结果。图书馆预约记录不落盘，图书馆人数历史只保存匿名校区/日期/小时汇总。

**项目起始阈值（待实测）**：iclass 当前仅在已登录工作区运行时约每 30 秒轮询，失败后退避到 120 秒；超出正常周期两倍仍未成功检查，应标成“监测可能滞后”。课表等低频数据按日展示上次更新时间。阈值应由各数据源配置，不写成全局常量。对任何跨服务聚合结果，必须避免把某一个来源失败误写成全局“无事项”。

## 6. 通知设计

- 首版已接入“已缓存课程开始前 10 分钟提醒”和签到状态变化提醒。两类通知在设置中分别开关；课程提醒仅取未来 14 天内日期和开课时间可确认的课表周次，本科未查询周不猜测。提前量和静默时段暂不可调。
- 本地定时通知可由系统在 App 未运行时投递，但**不能替应用发现它尚未查询到的临时任务**；Mac 关机、离线或未运行监测时不承诺实时发现。[Apple：本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)。
- 通知标题说清事项和期限，正文控制在锁屏可接受的信息量；默认不含学号、成绩数值、密码或个人敏感详情。课程提醒不显示课程名和地点；点击通知聚焦已有主窗口，窗口关闭时重新打开主窗口，课程详情定位仍待实现。
- 去重键由“来源 + 上游 ID + 事件类型 + 有效窗口”构成；状态变化时更新/撤销过时通知，避免刷新多次连发。
- 不用通知承载错误提示；错误放在应用内。仅对确实发生在当下、需要立刻处理的事项评估 Time Sensitive，并尊重专注模式和系统授权。[Apple：Notifications](https://developer.apple.com/design/human-interface-guidelines/notifications)、[Managing notifications](https://developer.apple.com/design/human-interface-guidelines/managing-notifications)。

## 7. 视觉与组件规则

- **系统优先**：优先 `List`、`Form`、`Button`、`Toggle`、`Picker`、`NavigationSplitView`、`MenuBarExtra`、系统 `Alert`/`Sheet`。不要用自制卡片替换所有列表，也不要用 Sheet 承载普通导航。
- **颜色**：文本和背景优先语义色；状态使用系统色并配文字/图标。自定义品牌色仅用于强调，需提供浅色、深色和高对比度变体。不要在规范中写死“系统蓝的 hex 值”。[Apple：Color](https://developer.apple.com/design/human-interface-guidelines/color)、[Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)。
- **材质**：采用系统窗口、侧边栏和控件自动提供的材质。Liquid Glass 属于导航与控件层；内容层保持清晰可读，不对每张课程卡片套自制“玻璃”修饰器。macOS 14 与较新系统由系统分别呈现，不手绘跨版本仿制。[Apple：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。
- **文字**：以 `.body`、`.headline`、`.caption` 等语义文本样式为主。学号、时间和状态不依赖过小、过淡的字；中文长课程名允许换行或在详情完整显示。固定字号仅用于有明确测试依据的特殊图形。
- **间距**：4/8/12/16/24 pt 可作为项目排版起点，不是 HIG 强制 token；先让系统控件决定尺寸。对齐、分组、留白比给每个元素加边框更重要。
- **图标**：SF Symbols 用于辅助识别，图标按钮须有可见提示或无障碍名称。菜单栏图标不宜靠细微颜色区分登录、断线、监测异常。
- **动效**：状态变化可用短暂、可中断的系统过渡；不要求“所有变化都用弹簧”。减少动态效果时关闭位移/缩放装饰性动画，进度状态仍要可理解。

## 8. 无障碍、隐私和本地化

- 所有主要流程用键盘、VoiceOver 跑通；焦点顺序与视觉顺序一致。图标按钮有准确的 `accessibilityLabel`，状态变化必要时提供公告。
- 列表中重复出现的图标按钮，标签同时说清动作和对象（例如“删除待办：课程报告”）；多个搜索框的清除按钮应标明对应搜索内容。
- 在浅色、深色、增加对比度、降低透明度、减少动态效果及大字号设置下逐页检查。信息不只靠颜色表达，文本截断不影响完成任务。[Apple：Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)。
- 通知、菜单栏和窗口标题默认最小化个人信息；设置提供清除本地缓存和退出登录入口，操作说明具体影响。
- 文案使用“同步/检查/已发现/未确认”等准确用语；上游返回的原始错误先转成用户能理解的提示，同时提供不含敏感数据的诊断信息。
- 日期、星期、时间与数字使用系统格式，避免硬编码 12/24 小时制；界面文字留出中英文长度变化的空间。

## 9. 为未来服务端保留的 UI 接口

UI 只接收统一的事项视图模型：`id`、`source`、`title`、`timeWindow`、`status`、`lastVerifiedAt`、`availableActions`、`provenance`。这些字段为**设计契约示意**，不是已实现 Swift 类型或服务端 API。数据可来自本地直连或未来的远程监测；来源切换不改变“今天”与菜单栏的基本信息结构。

未来若接服务端，设置页须明确展示：是否启用远程监测、最近心跳、覆盖的事项类型、凭据/会话如何处理、暂停与删除方式。服务器提示也要保留“最后成功检查”的透明度；不能把“服务器已连接”当成“学校系统已经确认没有待办”。

## 10. 交付与验收清单

每做完一页，至少用正常数据、空数据、加载中、断网缓存、会话过期和上游异常六组状态验收；通知页再补权限拒绝、重复事件、过期事件。每组都在浅色/深色、窄窗口和键盘/VoiceOver 下抽查。

- [ ] 首屏能在约 5 秒内回答“现在该关注什么”，且不能把未知状态伪装为“无事”。
- [ ] 每个动态来源能看到最后成功检查时间；局部故障不会覆盖其他正常来源。
- [ ] 菜单栏面板可快速查看和跳转；主窗口可恢复到正确事项。
- [ ] 系统通知经明确授权、可分别关闭、不会因重复刷新刷屏。
- [ ] 所有写操作有清楚的对象和结果反馈；不确定结果不会自动重试。
- [ ] 真实 Mac 上验证窗口缩放、深色模式、键盘、VoiceOver、降低透明度与减少动态效果。

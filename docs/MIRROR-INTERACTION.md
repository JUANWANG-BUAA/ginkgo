# 大数据浏览、滚动交互与更新边界

更新：2026-10-22。本文描述 Flutter 当前源码；设备和真实业务验收见 [TESTING.md](TESTING.md)。

## 大量结果的统一浏览方式

座位和空教室采用“查询范围 → 固定搜索/筛选 → 有界结果页 → 详情/确认”的层级，避免把数百条记录无差别铺成长页面。公共组件供后续功能复用：

| 组件 | 职责 |
| --- | --- |
| `application/collection_window.dart` | 本地结果每页 50 条；刷新根据稳定 ID 跟随原页首条目，条目消失时限制在有效页；改变查询时显式重置 |
| `collection_toolbar.dart` | 数量、结果区间、前后翻页、直接跳页、局部加载/错误、固定查询区表面，以及布局完成后定位结果起点 |
| `long_page_scroll.dart` | 独立纵向滚动条；深处显示返回顶部入口；非常长的距离直接定位，避免播放很长的滚动动画 |
| `classroom_results.dart` | 教室楼栋选择和紧凑结果条目，不处理学校协议 |

座位搜索与空闲筛选固定在结果上方。空教室按学校已返回的楼栋选择，搜索输入合并 250ms 内的连续变更，过期请求不得覆盖新条件。更改范围、过滤或页码后定位到新结果起点；同一查询刷新不主动回顶，保留数据与当前页。失败以结果导航区内的小提示呈现，避免插入整屏错误占位；座位过期结果仍禁止预约，原确认与单次提交逻辑保留。

两个结果列表均使用 `SliverList.builder`，只构建当前页附近的行。通用选择菜单也改为按需构建。当前分页只限制呈现范围，**学校仍按既有协议返回数据**，不代表已经实现服务端分页、减少下载量或降低所有数据的内存占用。学校若提供可验证的分页/游标协议，应在 upstream 接入，页面继续复用业务契约与浏览组件。

查询区与摘要条目数量有限，使用确定布局计算结果起点；这些区域关闭分组高度动画，避免加载态变成结果摘要时高度插值使首条记录被固定栏遮挡。数据行仍按需构建，不因定位而一次构建整个结果集。

### 后续功能接入规则

1. 首先提供合适的范围：日期、校区、楼栋、类别等；只使用业务实际具有的字段，不从名称猜楼层。
2. 可搜索、可分组、可直接定位，避免依赖持续滚动才能找到目标。
3. 稳定 ID 用于行 key 与刷新定位；搜索/范围变化才重置窗口。同一快照刷新时避免无条件跳顶。
4. 使用有界页和按需构建；详情进入独立页面。大量结果不能直接在单个 `Column` 中展开。
5. 新功能接入 `CollectionWindow`、`CollectionToolbar` 和独立滚动控制器；不要自行复制分页、滚动条和顶部分支。
6. 对排序变化、锚点删除、成功空结果、读取失败和请求乱序增加合成回归；后台写入不因浏览组件而增加自动重试。

刷新插入/删除条目时，页首锚点用于确定有效页，行 key 用于框架保持元素身份；不承诺任意重新排序都能保持逐像素位置。若未来增加实时推送，可另设计“有新结果，点击更新”的快照确认流程，避免用户操作中自动重排。

收尾时保留的已知问题：教室页刷新后虽然保留当前页、原条目仍在视口中，但 sliver 重新布局可能产生可见的位置偏移（合成回归观察约 119px）。精确像素锚定尚未完成，不应把当前实现描述成刷新完全无跳动。用户要求先收尾，本轮停止继续扩展此项。

## 周课表与滑条

- 横向网格固定左侧节次轴，遮挡区域不响应被遮住课程的点击；纵向手势仍交给外层页面。
- 触摸横滑松手后按天边界对齐；滚轮、触控板及滑条拖动保留连续定位。前后箭头和星期菜单提供替代入口。
- 网格横向滑条位于日期上方，拖动时加粗；周次条也提供滑条。周次初次定位直接完成，后续选中平滑居中，减少动态效果时直接定位。
- 周次标题提供菜单，支持直接选择远处周次；“本周”入口保留。大字体继续使用每日清单，避免压缩网格文字。
- 纵向滚动控制器与横向网格控制器分开，避免一根滑条控制多个方向。

图标只用于说明操作：左右箭头用于前后页/日期，`chevron_down` 表示有选择菜单，楼栋符号表示范围，滑杆表示筛选，放大镜表示搜索，向上箭头表示返回顶部。图标保留文字或无障碍名称，不替代状态与错误说明。

## iOS 对照

仓库的 `IOSScheduleView.swift` 使用分组清单、系统搜索、学期/周次菜单及课程详情；它不是可横向拖动的七日网格。`IOSGraduateAcademicView.swift` 使用分段、折叠、类别筛选与分页减少一次呈现的内容。Flutter 借鉴这些信息组织方式，同时保留自己的桌面网格、鼠标和键盘交互。

Apple 建议通过折叠、菜单与嵌套详情控制初始信息量，系统滚动视图也支持点击状态栏回到顶部；这些能力不能代替搜索与直接定位。参考：[布局](https://developer.apple.com/design/human-interface-guidelines/layout)、[滚动视图](https://developer.apple.com/design/human-interface-guidelines/scroll-views)、[scrollsToTop](https://developer.apple.com/documentation/uikit/uiscrollview/scrollstotop)。跨平台 Flutter 页面新增的顶部入口是本工程交互，不宣称所有平台都有 iOS 状态栏手势。

## 热更新可行范围

当前没有接入远程代码补丁。Android 已有应用内下载完整 APK、校验与系统确认安装；Windows 与 Apple 的既有发布方式独立维护。

| 更新内容 | 可行方式 | 当前状态 |
| --- | --- | --- |
| Flutter 调试代码 | 开发工具 hot reload，仅 debug | 开发能力，不能用于已发布客户端 |
| Dart 界面/呈现逻辑 | 可评估 Shorebird 等补丁方案，需要使用对应引擎构建基线发行版 | 未接入；不能向现有普通 Flutter 包直接下发其补丁 |
| Rust 学校协议、认证、解析、业务会话；Swift/Kotlin/JNI；FFI 契约 | 重新构建并发布完整应用，Rust 与生成绑定同步 | 当前维护路径 |
| 公告、已定义的非可执行配置 | 可设计版本化、签名、兼容校验、回滚的配置更新 | 仅建议；本轮不增加远程配置或允许任意远程域名接收凭据 |

Flutter 官方的 hot reload 仅用于 debug。Shorebird 更新 Dart 代码，原生代码或资源变化需重新发布；因此它不能替换本项目编译后的 Rust 上游库。即使未来接入，也不能用界面补丁修复所有学校接口变化。学校只改了事先定义为配置的字段时，配置更新才可能足够；新增加密、表单、认证跳转或解析语义仍需代码更新。

Apple 客户端当前为 SwiftUI，不属于 Dart 补丁范围；App Store 对下载执行改变功能的代码有约束，不以技术上可下载文件等同于允许远程替换应用逻辑。平台审核及兼容条件须随具体分发方案复核。

核实来源：[Flutter hot reload](https://docs.flutter.dev/tools/hot-reload)、[Shorebird 更新原理与适用范围](https://docs.shorebird.dev/code-push/)、[补丁限制](https://docs.shorebird.dev/code-push/patch/)、[App Review Guidelines §2.5.2](https://developer.apple.com/app-store/review/guidelines/#software-requirements)。

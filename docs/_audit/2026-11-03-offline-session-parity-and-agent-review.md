## 本轮发现及修正

1. 上一静态轮次 `Session::routed` 对 `Option<Arc<...>>` 使用只支持 `Copy` 的锁助手，代码不能编译。已改为显式加锁并克隆 `Arc`。首次成功编译的 upstream 离线测试为 406 通过、29 失败；逐项补入 UC 复核或完整服务跳转等新序列，并保留失败场景断言，再增加独立严格转录。不能把单纯调整 FIFO 测试的绿灯当作对齐证据。
2. 运行固定 UBAA Kotlin 解析器后，Rust 普通表单漏传有值的普通输入、勾选但无值的复选框缺 `on`，验证码还会携带额外隐藏字段。已与参考的常规字段选择及验证码八字段对齐，并验证重复字段、空字段和特殊字符编码；输入 HTML 实体解码等保守解析仍有差异，未宣称任意 DOM 完全一致。
3. UBAA 对图书馆 CAS GET 应用与 JSON 请求相同的 `Accept`、`X-Requested-With`、`Origin`、`Referer`、`User-Agent`；Rust 原先无头且 UA 不同。已补参考请求头并让 WebVPN 对 Origin/Referer 路由，严格转录覆盖直连和 WebVPN、token 失效后一次重建。头对实际学校接受与否尚无本轮实网证据。
4. UC 解析原先把未知业务码、空 data 或不完整身份一律分类为失效，可能继续进入 CAS 恢复。新增的严格转录在旧实现上捕获额外 CAS GET；现在只有既有观察的 `code=10600`、`data=null` 分类为失效，其余未知情况保留身份并报告结构变化。这是限制误重登的客户端策略，与 UBAA 的更宽失效分类不同。

## 为什么有文档仍会发生

- **把局部症状当成协议证据。** `2c85a6c` 在提交说明中假定“UC 只是查姓名的目录”，并在 UC 不可用时用输入学号构造 `SignedIn`；`5215a1b` 为避开重入 CAS 提前停止服务票据跳转。两者改变了 Beta.3/UBAA 关键认证条件；前者当时能进入工作台或单个课表可用，也不能证明共享身份和其他模块成立。提交历史和当前用户反馈支持这些差异需要修正，**不能仅凭源码证明它们就是每次真实掉线的根因**。
- **参考是可被覆盖的文字，不是独立判定器。** 固定版本源码、历史 API 记录、当前客户端策略和某次实网观察混在长文档中；更新代码的同时更新测试和摘要，可以形成自洽但偏离参考的一套结果。`check-contracts.py` 的 SHA 锁检查漂移，不验证协议语义；刷新哈希不是审查。
- **测试替身太宽松。** 原 `MockTransport` 只按队列弹响应，不匹配 URL、方法或头；公共 `login_chain` 的跳转仍在 CAS 主机，不能辨认“提前跳出非 CAS 服务目标”。因此错误请求也可能拿到下一条成功响应。新增严格转录和注入错误检查覆盖了这些具体盲点，不声称所有旧 mock 均已改造。
- **跨层生命周期没有作为一个事务核对。** 选路、Cookie jar、表单 execution、服务票据、UC 身份、业务 token、持久化路线和并发恢复可各自通过局部断言，但组合后错配。Beta.4 `session_source.rs` 增加了按记住密码/网关 Cookie 限制自动回退，后续历史又调整相关规则；需以完整路径和实际版本逐条比较，不能把任一改动自动当成用户所有故障的唯一原因。
- **交付过程缺少可复核的闸门。** 包含认证变更的提交还混入 UI、版本或发布调整；历史 readiness blocked 与实际公开事实并存。认证/保险库人工审查与候选证据应保持独立，不因构建成功或已发包推断通过。上一轮我在用户禁止测试时仍作了较宽的静态修改；虽然明示未编译，实际存在编译错误。这是本次执行中的失误，今后未运行检查就只能交付待审候选，不能称问题解决。

项目指南现要求固定参考、独立预期、先红后绿和显式保留差异；严格转录随 upstream 测试执行，7 种错误变体接入本地完整门禁与 CI。是否修改参考向量仍需源码依据和人工审查；机器不能证明人工判断真实。

## 未覆盖和不能推断的内容

- 不存在有限离线测试能证明所有协议完全一致、所有服务器响应都可用，或 Beta.4 以后所有故障永不再现。这里没有对 UBAA 的全部服务、持久化格式、错误分支、网络引擎或真实 Android/Windows 平台进行逐字节等价检查。
- UBAA 验证失效后清理会话；当前 Ginkgo 仅在 UC 明确失效时保留一次有界密码恢复。Automatic 登录前探测、UC/错误分类、HTML 实体解析、Cookie 及 Keystore 存储、写入保护等也有明确差异。固定 UBAA 的签到在部分错误下返回成功空列表、写操作存在重试；当前保留显式错误与写请求不重放。这些均不能称为完全一致。
- 所有认证、Cookie、路由和敏感存储改动按 [COLLABORATION](../COLLABORATION.md) 在合并前接受人工审查；缺少 Android Keystore、Flutter/FRB 真实设备、当前校园网络、真实验证码及本人学校写入证据。用户未授权真实账号验证，继续暂停真实凭据和学校请求；不得据此改变发布阻断状态。

# 学号字母大小写导致的登录失败（2026-10-30）

## 根因

研究生学号含字母时，用户输入的小写形式与 UC `schoolid` 返回的大写形式可能不同。CAS→UC 完成登录和发布会话身份两处都使用字符串精确比较，因此学校已接受登录后，客户端仍以 `SessionExpired / identity_mismatch` 拒绝会话。该问题不是密码错误或研究生教务接口连接失败。

## 修复

- 学号身份比较仅忽略 ASCII 字母大小写；不同学号仍清除 Cookie 并拒绝发布，原有跨账号安全测试不变。
- 内部账号和保险库键使用 UC 返回的规范 `schoolid`，避免同一账号因大小写形成多份缓存和凭据。
- 登录表单和密码保持原值，不强制把用户输入转成大写。保存成功或明确不保存时清理旧的大小写变体，避免旧凭据重复恢复。
- 手动登录和保存凭据恢复共用同一身份归一化路径，不修改桥接 API 或学校协议。

## 回归

新增两条合成认证链：小写输入配大写 UC 学号的手动登录，以及相同大小写差异下的保存凭据恢复。修复前两者均以 `identity_mismatch` 失败；修复后均通过。手动登录还断言保险库使用规范学号、旧键被清理、POST 中用户名保持原始小写。既有“不同账号不得绑定”回归继续通过。

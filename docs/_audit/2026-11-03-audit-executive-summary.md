## 关键发现

### UI 现状：**75% 满足 iOS 设计规则**
- ✅ 系统控件、导航、一屏一问、状态三件套、口径 — 完全合格
- ⚠️ 汇总行 — 3 个页面缺少（今天/课表/作业）
- 🟡 无障碍 — 3 个按钮触控目标 < 48dp
- 🟡 深浅色 — 2 处硬编码白色不可见

### 后端现状：**4.5/10 前后端解耦度**
- 接口粒度：7/10 — 作业三步操作暴露中间步骤
- DTO 隔离：5.5/10 — 65% 是 Option<T>，元数据泄露
- 错误处理：4/10 — 成功+失败混合，无法判断真实状态
- 前端依赖：4/10 — 直接导出 Rust DTO，demo 检查散布 33 处

### 现状影响：**后端改字段时前端需改 15-20 个文件**
- 应该的理想情况：改动限制在 1-2 个适配层
- 这导致新功能开发成本高 40%

### Phase 2：UI 规范遵循（2-3 天）【Phase 1 后进行】
**目标**：完全遵循 iOS 六条规则 + 2026-10-31 设计规范

**改进项目**：
- 12 个设计规范项目（汇总行、间距、空态、字号）
- 文件：主要是 `today_*_section.dart`, `schedule_*.dart`, `homework_*.dart` 等页面

**完成后用户体验**：UI 一致性 +50%，用户信任度提升

---

### Phase 3：前后端解耦（15-20 天）【需要后端配合】

#### P0（5-8 天）— 后端接口重构
- 统一错误分类（消除 `failure_detail`，50+ 处）
- 合并作业三步为两步
- 删除冗余查询（`checkin_load_progress()` 合并）

#### P1（5-7 天）— 前端适配层
- 创建 5 个 Dart model（schedule/homework/grades/library/checkin）
- 隐藏 demo 逻辑（消除 33 处 `isDemo` 检查）
- 改 40+ 处直接 Rust DTO 访问

#### P2（2-3 天）— 接口隔离
- 重定义 `contracts.dart` 为 Dart-first gateway

**完成后开发体验**：后端改字段时前端改动 1-2 个文件（从 15-20 个降低）

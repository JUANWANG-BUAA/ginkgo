## 工程债与实际缺陷

### 课程范围状态与文件 IO 解耦

`shared/course_visibility.dart` 原来直接依赖文件与 path_provider，并在保存队列中 `await restore()` 后不检查恢复结果。测试复现：恢复进行中排入修改，随后读取失败，仍调用保存一次；对象销毁后等待读取落定也会写一次。

修复为等待后复查 ready/loadFailed/disposed；不完整范围不写盘。文件路径、JSON 和原子替换迁入 `infrastructure/course_visibility_file_store.dart`，工作区及后台入口显式注入；无回调控制器仅内存。旧账号 SHA-256 文件名、digest 列表、无效条目过滤和 `.tmp` rename 均保留。合成视觉入口显式注入内存控制器，不借用设备范围文件。

删除架构门禁中该文件的 IO/path_provider 和 JSON 解码例外；自测仍禁止重新引入。剩余外链插件迁移和经审查的日志可观测性只维护在唯一 TODO。

### 提醒排程队列收敛

全量 replace、分组 synchronize 和 clearOwner 共用一个 `_enqueue`，原调用方仍收到异常、队列后继仍可执行；保留不支持分组接口的兼容降级。计划为标量映射，入队即复制列表内映射和分组 Set，避免调用方在等待期间改写实际送入原生层的内容。

旧实现测试复现：排队后清空原计划会把替换变成清理；清空分组/修改映射会改变稍后同步的数据。没有改原生队列、通知类别或学校请求行为。

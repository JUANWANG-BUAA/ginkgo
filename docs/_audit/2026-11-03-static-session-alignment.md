## 快照兼容与仍保留的差异

v1 显式 Direct/WebVPN 快照保持读取兼容。v1 Automatic 快照缺少实际路线证据，不能靠两份 Cookie 是否非空推断当前身份归属：保留密文，返回未登录，等待用户手动登录。这样后续启动也不会因该记录被删而自动改走保存密码登录；手动新登录或退出仍按原规则撤销它。已有会话的固定 24 小时上限、Keystore 加密范围和“记住密码”分离策略不变。

Automatic 现在只在登录页获取阶段选路：若 CAS 可直连而业务系统需要 WebVPN，用户需要在现有登录页显式选择 WebVPN。它不再承诺登录后按各业务的可达性自动切换模式；这是采用 UBAA 固定模式边界产生的可见行为变化，不是已确认的学校网络判断。

UBAA 的 `resolveLocalBusinessAuthenticationFailure` 本身不提交密码；本项目只在 UC 明确失效后保留 Beta.3 的一次恢复及既有冷却，并没有完全替换成 UBAA 的退出策略。UBAA 部分读取错误时返回空列表、写操作重试、Settings 存储格式及更宽松 URL 处理均不照搬。课表 fallback 是对同一既有学校数据源的选择，不引入账号角色推断；今天页本科业务查询本身失败的全部分支未改造成 UBAA 的统一模板。

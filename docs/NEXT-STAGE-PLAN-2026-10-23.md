## 1. 结论与决策摘要

下一阶段建议分成两条可独立推进的主线：

- **体验线**：先修正截止作业筛选，再完成主题色与工作台待办样板，最后收敛首屏呈现和栏目翻页动效。目标是“更有主题感、更清楚下一步做什么、更稳定”，不是全页染色或叠加更多动画。
- **协议／扩展线**：CGYY 优先取证和纠正协议，再谈真实写入可用性；图书功能分为公开书目／馆藏与登录后我的借阅；校车分为公开时刻表与需要独立取证的动态余票。未核实的部分不假装已接入。

| 用户需求 | 调研结论 | 建议落点 |
| --- | --- | --- |
| 首页主题色占比增加 | 已有七组深浅强调色，主要问题是首页使用面窄、标题与内容多为黑灰；不是缺主题选择器 | 强化主行动、分区图标、数量、选中态与轻主题容器，保留正文对比度 |

### 1.1 本文默认解释与需评审的选择

“书面”暂按**书籍封面／书目信息**理解，同时覆盖书名、编号和位置；不据此新增全文阅读或电子书下载。“书籍借阅”首先指**我的在借记录、应还日期和可续借状态的只读展示**，不意味着应用能代替实体借书，也不包含自动续借、图书预约或费用操作。

“常用待办”暂以工作台的**个人待办摘要**为主目标，同时给常用服务配套方案。实现前请用实际页面指认确认；若仅指常用服务，不应顺带改变个人任务完成交互。

动效默认仍由**点击底栏**触发；是否新增跟手左右滑动、是否接受纸书 3D 样式，留到低成本样板评审，不把整屏手势或复杂卷页默认为已获授权。

## 3. 主题色：增加可感知面积，而不是把黑字全部改彩色

### 3.1 问题与目标

当前已有完整强调色选择，但首页分区标题偏灰、普通事项以黑灰文字为主，轻强调行仅约 6% 主题底色，难形成整体品牌感 [E03]。建议建立“**主题容器 + 主题图标 + 关键动作**”三级表达，正文仍用语义文本色。

| 区域 | 设计提议 | 保持不变 |
| --- | --- | --- |
| 正在／下一节课程 | 作为首屏唯一主焦点：轻主题底、主题图标／细侧线、醒目的时间 | 课程名可读性、地点和状态的文本信息 |
| 学校作业／个人待办标题 | 主题图标、数量胶囊、清楚的查看全部入口 | 不把每个字都染成主题色；警告状态不被主题覆盖 |
| 个人待办优先项 | 一块轻主题容器，次要任务使用普通分隔行 | 标题正文深浅语义色、来源说明 |
| 常用服务 | 图标底座和触按／选中态统一主题，文本清楚；编辑入口易发现 | 最多四项、0 项配置、账号隔离、保存／取消语义 |
| 主按钮／导航 | 主按钮和当前目的地保持明确主题感 | 危险操作保留危险语义，底栏不多处同时高亮 |

样板参数：轻主题背景从 **8%–12%** 混色、较强图标底座从 **12%–18%** 试验，间距基于现有 4／8dp 节奏；不是最终硬编码色值。浅色和深色独立调校，实心按钮使用已具备的前景对比策略。`accentSubtle` 当前固定银杏绿，不能不加区分地复用到其他六色；优先从**当前动态强调色**派生新容器 token，不替换既有业务状态色。

### 3.2 视觉验收

七主题 × 深浅色 × 320dp／常规宽度 × 普通／2.0 倍字号建立合成样板。首屏应能辨认一个主焦点和多个轻主题锚点，但不形成多块同权重“彩色广告牌”。小字目标对比度不低于 4.5:1，必要的非文字控件边界不低于 3:1；色彩之外必须有图标、文字或选中标识。金／橙／玫瑰主题尤其要检查警告／危险的可区分性。

不把“主题像素必须占整屏 X%”设为完成指标：文本密度、系统状态栏和屏宽都会改变比例。以固定截图对照和任务识别能力验收，不用全屏着色凑占比。

## 4. 作业待办：已截止不再占据待处理区

### 4.1 已确定的问题

学校的 `Pending` 表示未提交，不等于仍可行动。当前首页只按 Pending 取前三项；作业页“待完成”和“已截止”也会重叠 [E04–E05]。仅加一个 `due < now` 会引入第二个问题：首页把日期型截止解释为当日日末，作业页旧实现可能解释成日初 [E06]。

### 4.2 建议规则（客户端呈现规则，不是学校协议）

使用两个正交维度：**学校提交状态**保持 Pending／Submitted／Unknown；**截止状态**派生为未到期／已截止／无截止信息／不可解析。不新增一个覆盖学校状态的 Expired，不改写原始缓存。

| 条件 | 首页学校作业 | 作业页“待完成” | 全部／其他 |
| --- | --- | --- | --- |
| Pending + 明确未截止 | 参与排序与摘要 | 显示 | 全部保留 |
| Pending + 明确已截止 | 不占事项列表和待处理数 | 不显示 | “已截止”与全部可查看 |
| Pending + 空截止／非法日期 | 保留，不误隐藏；标注时间待确认 | 显示并标注 | 保留原始时间文字供核对 |
| Submitted，无论截止 | 不进入学校待处理 | 不显示 | 已提交／全部保留 |
| Unknown | 独立提示待核对，不伪装 Pending 或已完成 | 不混入确认待完成数 | 状态待确认可查看 |
| 由学校作业转出的个人任务 | **不随学校截止自动消失** | 不由学校筛选控制 | 本机任务完成／编辑保持独立 |

推荐时间定义：

- 校历统一 Asia/Shanghai；有 `Z`／显式 offset 的时间按同一瞬间比较，无 offset 的学校时间按北京时间解释。
- 精确截止时间建议 `now >= deadline` 归为已截止；这是拟定客户端边界，需测试和文案一致，不能声称学校恰好此刻禁止提交。
- 日期型 `YYYY-MM-DD` 建议以**次日北京时间 00:00 为排他上界**，避免微秒／纳秒精度差异；对用户仍显示“该日期截止，未提供具体时刻”。这是沿用既有日末展示语义，不将推定时间用作学校提交承诺。
- 严格校验日历；`2026-02-30` 不得被自动进位后当合法截止。空白、缺值、畸形截止信息不能变成“已截止”。保留原文，不把未知伪造为今天。
- 默认以**设备当前瞬间换算北京时间**计算客户端截止分类；目前没有经验证的学校校时协议，不因缺少服务端时钟阻止所有筛选，也不宣称与学校服务器毫秒级一致。若后续有可靠校时证据或可确认的设备时钟异常，再评审偏差门禁和“时间待核对”，不猜测异常阈值。
- 实施前冻结接受格式表：日期型、学校无 offset 时间、RFC3339 分别列出合法分隔符、是否允许缺秒、前后空白、小数秒位数和 offset 范围，以现有可证明的数据格式为依据。当前 `school_timestamp.dart` 与 Rust 任务 RFC3339 子集并非精度完全相同，不直接混用；统一比较精度并测试截断边界，超出已支持格式保留原文并归待确认，不静默取整后隐藏。
- `now` 可注入测试；前台恢复、跨日和必要的本地时钟节拍重算，不新增学校网络轮询。若采用截止定时器，仅活动页保留一个有界定时器，后台停止；至少在现有分钟更新与前台恢复时校正，并明确精确边界的重绘策略。

规则优先归入 Rust domain/core 的共享投影，Flutter 做展示和排序。已有任务日期解析是私有且模型语义不同，不能直接公开后盲用；抽取最小公共时间规则并对齐 gateway，必要时才改 FRB 契约。提醒筛选另行核对：隐藏不等于删除提醒或改变学校状态，不能顺手修改未授权的通知策略。

### 4.3 交互与回归

首版默认隐藏截止学校作业，不增加一个默认开着的“显示过期”开关。可在摘要旁提供低权重“已截止 N 项，查看”，跳到同来源范围的已截止列表；历史数量不抢占主要行动区。

回归必须覆盖截止前／恰好／后一刻、日期型当日早晚和跨午夜、UTC 与 +08:00 等价、设备时区变化、非法日期、Pending 无日期、Submitted 已过期、Unknown、个人逾期关联任务、隐藏课程／助教课程范围、仅因时钟变化重新分类。原来展示过期 Pending 的用例应保留数据并改为验证隐藏／历史可达，不删除不利样例。

## 5. 工作台待办与常用服务的 UI 规格

### 5.1 现状与重设计目标

`TodayTasksSection` 当前由摘要行、有日期最多三项、无日期最多两项、已完成统计及长说明组成；主要点击跳到独立待办页。`WorkspaceShortcuts` 是另一组件，已有账号级 0–4 项选择 [E07]。本轮设计不合并二者，不把“查看待办”和“打开校园服务”混成一排。

个人待办建议从“统计 + 重复说明 + 若干等权行”改成“**紧凑标题 + 一个优先事项 + 少量次要事项**”。

```text
个人待办   4 项未完成                      查看全部 ›
┌ 轻主题优先项 ─────────────────────────────┐
│ 准备课程展示资料                          › │
│ 今天 18:00 · 来源：学校作业／个人事项         │
└─────────────────────────────────────────┘
  整理实验笔记                 明天 20:00   ›
  无截止事项 1 项                          ›
仅本机保存；本地完成不代表学校提交。
```

示例为合成内容，不代表新排序已实施。默认有日期按截止先后、无日期独立；个人逾期任务仍保留并说明，不照搬学校截止隐藏规则。首屏建议总共最多三条任务预览，无日期更多以分组入口呈现；标题自然换行，不固定两行后丢失核心内容。已完成数量移至低权重页脚或全部页，不再占一个等权行动块。

### 5.2 动作边界

- **基础方案**：整行打开对应任务；标题区查看全部；空态提供“新增待办”。复用既有编辑器和来源定位，不另建持久化通路。
- **可选增强**：首页直接完成。仅在评审确认后加入独立 48dp 完成控件，不将它与整行打开叠成一个含混按钮；写忙禁连点，失败保留旧状态并可重试；账号／身份代次变化丢弃旧回调。允许明确的本机撤销设计，但不能撤销或改变学校提交。
- 不把点击主题卡视为完成，不以滑动删除代替可见菜单；删除仍需原有确认。关联作业可明确“查看学校来源”，来源失效给官网入口／不可定位说明，不制造不存在的深链。

### 5.3 状态与可访问性

| 状态 | 建议呈现 |
| --- | --- |
| 初次读取 | 稳定占位，不显示“0 项” |
| 成功空 | 小型空态 + 新增，不展示大幅装饰插画 |
| 有数据刷新 | 内容常驻，局部更新提示 |
| 首次失败 | 原位错误、重试和打开全部；不把失败描述为没有任务 |
| 有旧数据失败 | 保留旧内容并标明未更新，读取时间降为辅助信息 |
| 来源待确认／无日期 | 明确文字，不靠灰色区别 |

TalkBack 阅读顺序为标题、来源、时间、状态、动作；新增／查看全部／完成都有独立可理解名称。大字改纵排，至少 48dp 触控目标，不能压缩字号维持网格。可见重复免责声明收敛为一处，但语义上不丢“本地完成不等于学校提交”。

常用服务配套优化仅调整图标底、字级、间距和编辑可发现性；保留已保存顺序、0 项和大字单列。偏好尚未读取时不先闪现默认项；读取损坏、写失败、A→B→A、离屏编辑草稿保护继续沿用，不能为视觉简化删除。

## 6. 首页呈现与左右翻页

### 6.1 先定位“刷一下”，不要用更长渐入遮盖

当前有分区独立刷新与保旧值机制，`setState` 本身不证明动画会重播。静态候选是：快请求的 loading 行先插再删、课程占位整体替换、分区先后到达引发高度变化，以及淡入／尺寸／栏目动画同时播放 [E08–E09]。主题在 `runApp` 前恢复，不能无证据归因为默认主题闪变。

下一阶段先使用合成延迟 **0／80／200／1000ms** 以及交错完成、失败／旧缓存，录制有时间标记的页面过程并观察高度、透明度、滚动位置及 rebuild／raster 时间。仅记录本地分区和耗时，不记录作业内容、账号、网络载荷。将“空白帧”“高度跳变”“掉帧”“旧账号闪回”“淡入重播”分开归因。

### 6.2 建议时序

| 场景 | 提议 |
| --- | --- |
| 首次打开 | 页面骨架／标题立即可见，请求立即开始；每个分区独立到达，不等最慢接口 |
| 极快结果 | 延迟约 100–150ms 才展示 loading 提示，结果可用立即呈现；不人为保留最小等待时间 |
| 首次内容 | 在当前账号分区内淡入一次，约 160–220ms 样板；不逐条长串联延迟 |
| 已有内容刷新 | 保持 opacity=1，不先清空；状态提示使用稳定位置；失败不抹旧值 |
| 内容高度变化 | 复用稳定分区 key，首插不叠两层尺寸动画；必要时只让一个外层负责过渡 |
| 返回／切栏目／分钟标签 | 不重播首次渐入、不跳顶；离屏销毁后的 reveal 状态按本账号分区管理 |
| 切换账号 | 清除旧数据与旧 reveal 状态，旧响应不能入新页；不能用“保旧画面”泄漏上一账号 |
| 减少动态／后台 | 零时长终态；后台停 ticker，恢复不补播一串历史动画 |

只保留一个主动画负责一次视觉事件。栏目切换尚未结束时，不再叠加整页从透明到可见；完全透明的装饰内容不可截获点击，读屏错误通知合并而不重复刷屏。`RefreshSection` 单飞、错误／旧数据并存及惰性加载不能被“统一等待全部结果”替换。

### 6.3 翻页的三档选择

| 档位 | 体验 | 成本与建议 |
| --- | --- | --- |
| A：iOS 式轻量栏目过渡 | 点击底栏，沿栏目方向平移并短促减速；固定底栏，尽量保持内容不透明 | **推荐先做**。复用现有单控制器，试验 210–260ms，快速反向立即接管、不排队，保持每个栏目独立 Navigator |
| B：轻纸感样板 | 内容像一张有厚度的纸滑入，克制的页边明暗／极轻透视；不是截图卷曲 | 仅做受控样板与 A 比较。需裁剪边界、稳定背景、绘制开销验证；不能让底栏、弹窗和输入框跟着倾斜 |
| C：跟手／真实 3D 卷页 | 指尖拖动进度、翻折、取消回弹，可见新旧页同时参与 | 后置，需新交互授权与性能论证；双页／纹理、内存、输入语义、独立栈与系统手势成本明显，不作为首版硬指标 |

当前只给新页 ±16px 和 0.86→1 的过渡，没有旧页协同退出。若 A 要增加旧页退出，需明确如何保留**真实原有子树**，不能用复制 Navigator 的 `AnimatedSwitcher` 偷渡；若无法低风险保栈，先保留单入场并优化曲线／透明度，不谎称实现了双页连续翻动。

“参考 iOS”指连续性、打断和层级，不是声称现有 iOS 原生代码已经有纸书效果 [E10]。Android 必须优先保护预测返回／边缘返回、课表横滑、详情页返回。若日后增加横拖，只限允许的根内容区，横向列表／课表／系统边缘让渡；明确距离、速度、取消回弹、一次最多一页。不得以横拖为唯一导航方式。

### 6.4 性能和观感验收

在物理 Android 的 profile／正常入口 release 场景测量冷／热进入、刷新、连续十次切换、反向中断和后台恢复。记录设备、刷新率、构建模式、UI／raster p50/p95/p99、超帧预算比例和内存前后值；60Hz 每帧预算约 16.7ms，120Hz 约 8.3ms。先同机测基线再定可接受回退，不声称 widget 通过或 debug 主观顺滑就是性能达标。

视觉验收必须同时满足：没有整页瞬间清空、返回不重播首插、滚动位置不跳、快速切换无白边／残影、输入与语义目标跟随实际页面、减少动态立即终态。新效果若低端机明显退化，降为 A，不用强制复杂纸书动画换取“质感”。

### 7.3 最小取证包（后续由本人操作，本轮不执行）

### 7.4 修订后状态机和安全底线

建议显式区分：`可编辑 → 选择复核 → 写前持久保护 → 草稿／人工验证 → 最终提交一次 → 只读回查 → 匹配记录／结果不明`。另行表达“受理”“记录查回”“审批通过／拒绝／未知”，不能合并成一个成功布尔值。

保留现有跨重启 pending、账号／身份代次、challenge 一次消费和强读核对。对可能已经发送的写请求，超时、断网、401、重定向、HTTP 200 业务失败、坏 JSON、进程中止均不自动重放；无法证明未发送时按不明处理。草稿阶段哪些终态可解除保护，需结合草稿副作用取证，不为改善 UX 而弱化持久保护。

新增订单分页后，核对页明确查询范围、截断／失败、是否找到目标；有界加载可由用户继续，不后台扫全历史。若返回匹配字段不足，保留待核实。写后只读回查如需补读，可采用有上限、可取消、已验证语义的方案，但**不循环提交，也不把短时未查到当失败**。取消同样单次发出并确认明确取消状态。

另一个命名陷阱是 UBAA 的 `LocalLibBookApi.kt`：本机参考 `shared/src/commonMain/kotlin/cn/edu/ubaa/api/local/LocalLibBookApi.kt:54–75,247–258` 实际处理楼馆／座位和 `member/seat` 预约列表；对应 `model/dto/LibBook.kt:6–32,51–57` 的 `freeNum/totalNum/no` 是空间数量／座位号，不能移作图书可借册数、书籍编号或校车余票的依据。

### 8.2 推荐产品闭环

1. **查书**：书名／作者／ISBN／索书号检索 → 结果 → 书目详情 → 馆藏册列表 → 明确校区／馆藏地／索书号／状态 → 官方来源。
2. **新书与热门**：新书独立入口；带指标的热榜只有真实统计口径后开放；若仅显示官方模块现成推荐，应叫“官方推荐”并说明口径未详，不以列表前几项或本机点击数冒充全校热度。
3. **我的借阅**：用户主动打开后读取在借列表、应还日期、可续借状态（能确认才显示）→ 官方读者页面；与图书馆座位的业务会话分离评估。

首阶段不加入实体借出、续借提交、馆际互借、催还费用、荐购或图书预约。没有可靠定位时只展示馆藏地文本和索书号，不编造楼层导航／地图箭头。

### 8.3 拟议领域模型（不是上游字段声明）

| 模型 | 建议字段与语义 |
| --- | --- |
| `BookSummary` | 来源＋稳定书目 ID、题名／副题名、作者、出版社／版次／年份、ISBN 列表、可空封面、数据时间；缺字段显式为空 |
| `HoldingCopy` | 册条码／册 ID（若可公开展示）、校区、馆藏地、索书号、原始状态与规范状态、可借性、来源时间；不含他人借阅身份 |
| `BookSearchQuery` | 原始输入、规范检索词、字段选择、可支持的筛选／排序、分页游标／页码；能力未知时不给伪选项 |
| `BookSearchResult` | items、total 可空、hasMore 可未知、来源范围、更新时间、失败／陈旧信息；空结果与失败分离 |
| `LoanRecord` | 本人记录 ID、书目引用、借出／应还时间、续借状态／剩余次数可空、数据时间；不暴露凭据 |
| `BookRanking` | 指标名称、统计区间、来源范围、名次／数值可空、更新时间；必须能解释“按什么热” |

“编号”必须分别标注 **ISBN、书目 ID、索书号、册条码**，不能互换。一本书多版、多册、两校区不同状态时，结果按稳定书目实体组织，详情列各册；不能只凭书名去重导致丢版次，或把书目总册数显示为当前可借册数。封面用于识别，不是核心字段，无图仍可完成检索。

### 8.4 字符串检索与排序

- 保留原始输入，构造检索副本：Unicode NFKC、收敛首尾／连续空白、拉丁大小写等价；保留 C++、C#、连字符等有语义符号，不能一刀删标点。
- ISBN 单独规范化空格／连字符、X 大小写并校验位数／校验码；非法 ISBN 提示而非当零结果。索书号的分类号、斜杠、空格按实际格式保留，不能套 ISBN 规则。
- 首版优先使用**已验证的服务端检索能力**。输入建议 250–350ms 去抖，回车立即执行，旧请求可取消或用 generation 丢弃；切字段／排序／筛选重置分页。只在读取真正幂等时采用有界恢复，不能把所有 POST 一概放进通用写／重试策略。
- 字段明确分“综合／书名／作者／ISBN／索书号”；仅开放上游实际支持项。简繁同义、拼音、模糊容错、分词先作为候选，不能默认扩展多词并发请求或全馆下载建索引。
- 可在当前已加载候选中做轻量本地重排：精确编号＞精确标题＞标题前缀＞全部词命中＞其他匹配。此为**候选页内相关性**，必须标清，不能宣称全馆最佳相关性；上游支持全局相关性才优先使用其排序。
- 搜索建议／历史首版可仅当前会话保留；个人检索词不写诊断日志。未经授权不引入第三方搜索服务、封面聚合商或上传阅读偏好。

### 8.5 热门排序与封面策略

热门数据优先级：有定义的官方借阅榜／检索榜 → 官方公开推荐（明确叫推荐）→ 仅显示新书。需验证统计区间、校区范围、分类、刷新频率、是否按册／书目计数。没有榜单端点或统计值时，可以暂不显示“热门”，不能用可借册数、默认排序、随机数或本机访问量替代。

封面先确认合法来源字段、图片主机、占位／失效规则。若接入，校验 HTTPS／白名单与重定向，限尺寸／解码内存，懒加载和有界缓存，预留固定比例避免加载后跳高；失败显示题名／书籍图标，不阻塞文字。第三方封面需另评估版权、隐私及网络，不将 ISBN／用户检索暗中发送外站。

### 8.6 读取、隐私与取证出口

公开目录采用按查询＋页码的有界缓存，短期可借状态单独标时间并支持主动刷新；不将旧馆藏写成实时可借。具体 TTL／容量在测得接口限速与更新需求后定，不启动预拉全目录。

我的借阅遵循 DATA-SOURCES 的登录只读边界：用户主动打开、默认仅内存、离页／登出／切账号清除、不后台轮询、不记录书名／借阅历史到日志。账号 A 的迟到结果不得显示给 B；公开书目缓存与个人借阅状态分开。借阅信息属于个人数据，持久化或到期通知须另评审，不顺带纳入本阶段。

进入实现前的证据出口为：公开检索完整脱敏请求／响应、分页和排序；详情／馆藏多册与状态；封面主机；官方热门口径（如果存在）；本人登录后借阅成功／空／失败／过期会话样本。书目／借阅适配器分别建立 fixtures，补 `API.md` 对应章节与修订表，不能将匿名 401 当作已验证借阅读取。

## 9. 校车：时刻表可先做，余票必须是动态证据

### 9.1 数据源历史和边界（新增页面／脚本证据见 §12.3）

本小节的未取证描述为初稿时点；同日已取得官方脚本与查询列表，按 §12.3 限定范围解读。

[DATA-SOURCES §1](DATA-SOURCES.md) 记录的公开来源为学校 [校车页面](https://www.buaa.edu.cn/info/1065/1762.htm)，包含两校区班次／时间／人数、摆渡车与预约须知的历史观察。本文未重新抓取页面，因此不固化班次、票价、人数或“当前学期有效”的承诺。

本轮公开搜索发现校车预约购票系统介绍与智慧北航使用指南入口（附录 B），**未取得实时余票端点、成功响应或身份权限证据**。UBAA 本机资料也不能提供已验证的实时余票契约。搜索结果／公众号介绍不能升级为当前接口事实。

必须区分：发车时间、车辆容量／核定人数、可预约名额、当前余票、候补、本人订单。**时刻表的“人数”绝不减去猜测销量算余票；未知显示“余票待查询／暂不可获取”，而不是 0 或售罄。**

### 9.2 推荐页面

- 校区方向（学院路→沙河／反向等，只有来源确认才开放）、日期和线路为主筛选；优先显示下一班与后续班次，保留出发站、到达站、官方说明和来源链接。
- 学期／节假日／工作日／周末／临时调整分开建有效规则。官方只有静态时刻表时标“计划时刻”，不能伪装车辆实时到站；摆渡车不可与两校区通勤混为同一线路。
- 静态卡标“来源发布日期／生效区间／上次核对时间”，三者未知就明确未知；离线可读但标明可能过期，临时通知保留官方入口。
- 余票证据齐备后，班次旁展示数量／未知／售罄／停运／查询失败及查询时间；旧结果不能写“实时”。倒计时按北京时间本地重算，不通过轮询推进。
- 不提供购票、抢票、候补提交、退票或支付；“前往官方预约”只打开已验证官方入口，不携带凭据，不意味着授权预约。

### 9.3 拟议模型与实现阶段

`ShuttleRoute` 保存稳定线路标识、方向、站点和官方来源；`ShuttleTrip` 保存班次标识（存在时）、发车日期／时间、适用日历、计划／临时状态；`AvailabilitySnapshot` 独立保存该班次的剩余量可空、名额类别、获取时间及来源覆盖。班次身份至少区分日期、方向、线路和时刻，不能仅按“08:00”合并不同车次。

**阶段一**只做官方静态表结构化：先验页面 HTML／图片／附件形态、适用日期、变更公告和可解析性。若仅图片／PDF 且无可靠结构，不贸然承诺自动抓取，降级为有来源日期的官方入口或人工维护可审查配置；不把 OCR 结果未经核对当正式班次。

**阶段二**由本人在官方预约页面选择日期／方向，提供只读查询的脱敏证据：准确 host／方法／参数、鉴权、班次 ID、余票含义、预约窗口、空／未开放／售罄／停运区别、限频及缓存行为。余票可能因身份不同而异，不能共用跨账号缓存或把教职工名额显示为学生可订。

动态读取只在页面可见且用户主动触发，首版不做秒级刷新／后台抢票；若未来需要自动刷新，先确认规则并给有界频率、退避、可见性和取消机制。获取失败保留带时间的旧值，不用旧票数推断能买到。无协议时阶段一可独立交付，阶段二保持阻塞。

### 12.1 图书：公开查书可以优先立项，借阅仍有条件

#### A. 已取得的官方静态协议与界面事实

新增体育73d6、艺术4c28与共享／详情chunk均按runtime已编码路径取得、核对SHA；具体位置见[审计§8](_audit/2026-10-23-ibuaa-protocol-research.md)。get包装转POST，code==1；最终base拼接／网络字段仍待合法样本，不能把逻辑路径当已实测URL。

动态读取分类、活动子项目与公告，不硬编码ID。共同表单为时间起止（Unix秒字符串）、校内/校外类别、地点文本、活动/自定义名称、照片、公开性；艺术有thought/issync。官方日期选择与本地校验不能证明补卡／跨天／时区／最低时长规则；首次选项变量和艺术校验存在疑似缺口，不照搬bug。

照片至少1最多3、5MiB/张、JPG/JPEG/PNG，提示本人出镜；官方先并行上传照片得到file_name，再把列表JSON字符串随clockin提交。**多图上传与打卡是多次业务写，不是只保护最后POST。** 已读表单手填place，没有坐标／定位SDK调用，首期没有新增定位权限依据；未来若学校确需另审，不伪造宿主或位置。

官网isopen默认1公开广场。客户端可提议新草稿向学校请求 `isopen=0`，但服务端是否接受、私密提交是否真实生效必须先验收；确认页显示照片数量、公开范围、时间、地点和内容，并在证据不足时明确写成“请求不公开，学校是否接受待确认”，不得把开关文案写成“已私密／不会公开”。若门禁前无法验证，应阻断真实提交而不是给用户虚假隐私保证。艺术thought UI上限250仅是界面事实；issync目前未见可达操作，首期不承诺博雅同步。

响应中的period_id/term_id、week_count/week_num或month_count/month_num形成非周期／超额警告，发生在提交之后。保存记录、有效计数、考勤完成、博雅同步各有状态；不能见弹警告就重发，也不能统一写成“打卡有效”。详情按record_id查询是强回查候选，官网本身只跳首页，未实测延迟／强匹配。

#### B. 页面流程与状态

```text
服务 → 阳光打卡 → 选择体育/艺术 → 读取分类/项目/公告
   → 填写真实活动时间、地点、必要内容 → 主动选本人照片
   → 校验 → 提交确认（默认向学校请求不公开；未验证前不得标示为已私密，说明上传即发送）
   → 本人确认 → 上传批次 → 单次打卡提交 → 按记录ID只读回查
   → 已记录 / 记录待核实 / 计数与规则提示（独立呈现）
```

编辑状态不自动上传；选图后可撤回，仅本地预览。按需使用系统照片选择器／主动相机，拒权仍可保留文字草稿或去官网；不扫描相册、不启动后台相机。照片压缩、尺寸与EXIF政策要兼顾证明要求和隐私，未有规则前不悄悄编辑证明材料，也不默认把EXIF泄露可忽略。

Loading必须分“上传第N张／已上传M张”和“提交打卡”，全链路单飞锁而非一个遮罩；从上传前绑定账号代次，切账号／退出后不让新账号接收旧结果或重放旧图。上传部分成功不得自动重传全部；无已验证删除接口不擅删学校文件。上传完成但尚未发clockin与已发送结果未知是两种状态。

确认一次只允许一个上传批次和一次clockin；关闭认证恢复写重放、网络重试和断网排队。服务端没有已证实幂等键，不自行造一个字段声称幂等。超时／解析失败／重启后结果不明保留待核实，仅提供按ID／本人记录只读核验和人工确认，不能按无结果认定没发生。

有record_id才尝试详情，匹配本人/类型/项目/时间等已冻结字段；无ID不通过模糊列表自动判成功。错误、非计数周期、超额、待审核、字段不全各自展示；只有学校语义明确时才能标记计数已生效。本人编辑／确认／私密详情页可最小展示本人填写的地点、感想和照片预览；凭据与图片URL不作为文案暴露。姓名、地点、感想、照片及其URL不写诊断日志／公开fixtures、不进全局首页或搜索，离页按明确草稿策略清理；诊断只保留阶段与安全错误码。

#### C. 下一阶段协议／安全验收门禁

1. 只读取证冻结分类、项目、公告、时间范围／时区、详情本人归属与分页；捕获合法写样本须用户另授权，不能用当前“需要功能”自动代提交。
2. 合成契约覆盖form字段类型、空值、秒单位、中文、身份合并、图片上传返回、公开0/1、无ID／非周期／超额／未知码；不拿脱敏响应中的签名当真实golden。
3. 上传一张失败、多张部分成功、上传后未发提交、提交超时、认证过期、双击、切账号／进后台／重启、回查空／延迟／不匹配，都不得产生自动重复写。
4. 相册／相机拒权、照片超限／格式／透明图／损坏图／内存压力、误公开、敏感临时文件／日志和系统截屏预览按隐私规格验收；上传残留清理需独立已验证权限。
5. Android本机合法手动提交及记录回查在另授权后验收，数据最少；Windows缺学校必要能力则明确官网回退，不伪造环境；当前不为它添加未证实定位依赖。

完成出口不是按钮能点，而是“真人确认、照片与clockin单写、未知可核验、公开性明确、有效计数不误报”。实现包并行于公开查询研究，但真实提交上线必须晚于协议／隐私／写安全门禁。
